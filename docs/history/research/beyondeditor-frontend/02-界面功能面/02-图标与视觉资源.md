# 02-02 · 图标与视觉资源

> **调查的问题：** `assets.bin` 里的图标/视觉资源反推出哪些功能面？
> **结论一句话：** 6,453 个资源**全部是 PNG 图标，没有一个是界面定义、XAML 或配置**
> ——所以它们**不能**用来解释「界面长什么样」；但它们反推出两块极具体的名单：
> **410 个工具栏按钮** 与 **2,424 个可放置元件**，外加 **2,973 个特效/元素视觉标记**
> 与 **646 个怪物/动物图标**（可信度：高，静态全量 + 清单与磁盘文件 100% 对齐）
> **最后更新：** 2026-09-22

数据版：`db/raw/icons.json` → 表 `icon`（6,453 行）。
查询：`SELECT bucket, count(*) FROM icon GROUP BY 1 ORDER BY 2 DESC;`

---

## 一、先证伪一条上一轮的推断（重要更正）

上一轮 `02-界面功能面/01-界面文本总表.md` §4.3 曾推测：

> 「完全无代码落点的末级桶（6 个，共 96 条）……`assets.bin`（加密，未解包）是它们最可能的载体。」

**这条推断已被本轮否证。** `assets.bin` 已经解开了（`.runtime/editor-catalog/assets-bin/assets.dec`），
内容是 **6,453 个 PNG，全部在 `ART/` 路径下，没有一个非图片条目**：

| 文件 | 条目数 | 扩展名分布 |
|---|---:|---|
| `assets.dec`（`assets.bin` 解出） | 6,453 | **png × 6,453** |
| `beyondeditorassets.dec` | 1 | png × 1（`BeyondEditorAssets/UI/Icon/Image/UI_MarkPlayer_Faction.png`） |

⇒ **`assets.bin` 不含任何文本、界面定义或配置**，不可能是那 96 条界面文案的载体。
正确做法是把那 96 条标为**「未找到载体」**，而不是指给一个已被排除的容器。

## 七、与文本 / 代码的对账

| 对账项 | 结果 |
|---|---|
| 图标名 → TextMap 键 | **0 命中**（2,424 与 410 里没有一个直接是 TextMap 键或去扩展名后是其键） |
| 图标名 → 代码字面量 | 未能匹配（图标名不在 2,738 个代码字面量里） |
| 图标名与元件定义文件名的关系 | **未建立**（`.mihoyobin` 用哈希命名，与图标名无字面关联） |

**怎么读这三个 0：**
图标名是**美术资源命名**（`UI_Beyd_Gadget_Build_House_01.png`），
而界面文本与代码用的是**资源 ID / 哈希**。两者之间隔着编辑器内部的资源注册表——
**图标不是通过名字被引用的**。这是本项目里又一次「grep 不到 ≠ 不存在」的例证。

> **未做**：没有去 `assets.dec` 里提取 PNG 做视觉核对（本轮以清单与命名为准）。
> 若后续需要确认某个图标长什么样，代表性命名的 PNG 可以直接从
> `.runtime/editor-catalog/assets-bin/assets.dec` 取（ZIP，标准库可直接读）。
