# 04 · 操作名与命令绑定

> **调查的问题：** 前端定义了哪些「操作名」，各自绑定到哪段代码？
> **结论一句话：** 编辑器代码里以**字面量**形式出现的 camelCase 操作名共 **44 条**（全量正则枚举，非抽样），
> 全部落在 **20 个混淆类型**上；其中 **9 条集中在两个「命令宿主」类型**
> （`kg9jHSKBgsfObR2IXdPf` 30 成员、`NQ6Rasu5Wb3lL511Sp4j` 72 成员），
> 其余按对象类别分流到实体 / 元件 / 标签 / 日志 / 特效 / 音频 / 窗口 等专门宿主。
> 这 44 条**就是「前端能对内容做的动作」的命令层全集**（可信度：高，静态全量枚举）
> **最后更新：** 2026-09-22

数据版：`db/raw/operations.json` → 表 `operation`（44 行）。
查询：`SELECT op_name, category, call_sites FROM operation ORDER BY op_name;`

## 一、方法与口径（重要）

| 项 | 做法 |
|---|---|
| 语料 | `.runtime/editor-catalog/annotated/`（12,375 个 `.cs`，字符串字面量已还原） |
| 枚举方式 | 词法扫描全部双引号字面量 → 用**动词首字母大写**的 camelCase 模式匹配：`(Add\|Apply\|Bind\|Build\|Clear\|Close\|Copy\|Create\|Delete\|Do\|End\|Export\|Focus\|Generate\|Get\|Import\|Init\|Jump\|Load\|Modify\|Move\|Open\|Play\|Refresh\|Remove\|Rename\|Request\|Reset\|Save\|Select\|Serialize\|Set\|Show\|Start\|Stop\|Sync\|Toggle\|Unbind\|Update\|Zoom)[A-Z][A-Za-z0-9]{2,60}` |
| 去重 | 按操作名去重，记录全部调用点（类型 + 文件） |
| 实现 | `db/extract-raw.py`（**单遍扫描**：一次读盘同时产出 operations / code-surface / textmap 三张表） |

**为什么用「字面量 + 动词模式」而不是别的判据：**
这些操作名**不是方法名**（方法名全被混淆了），而是**传给通用派发器的字符串实参**。
编辑器只有一种方式表达「我要做 X」——把 `"X"` 当参数传出去。所以字面量就是命令。

**口径边界（必须一起读）：**

1. 这 44 条是**在执行了字符串还原之后的语料**里找到的。程序集有 216 处字面量尚未还原
   （属尚未取到密钥的其它表），因此**不能排除还有操作名没被还原出来**。
   → 「44 条」是下界，不是上界。
2. 匹配模式含 `Get*`，所以混进了 4 条 **Win32 API 名**（`GetCursorPos`、`GetForegroundWindow`、
   `GetKeyboardLayout`、`GetWindowThreadProcessId`，P/Invoke 声明）。它们**不是编辑器操作**，
   口径上保留但需识别剔除。
3. 「有调用点」只证明**代码里存在这个字符串并用于调用**，**不等于该操作在游戏里可用**。
   见 `07-能力边界与缺口.md` §五 三条禁令。

## 三、按对象类别的动作矩阵（把上表转置后）

这张表直接回答「前端能对**这类对象**做什么」：

| 对象类别 | 支持的动作 |
|---|---|
| **实体**（EditObj） | 改名 · 删除 · 聚焦 · 改阵营 · 改标签 · 挂节点图 · 删组件 |
| **元件/预制**（Prefab） | 改名 · 删除 · 聚焦实例 · 改阵营 · 改标签 · 删组件 · 请求实例 · 应用实例变更 |
| **PCG 实例** | 改名 · 删除 · 聚焦 |
| **场景对象（按类别）** | 聚焦：角色 / 环境 / 光源 / 本地子弹 / 掉落物 / 千星地块图 / 截图 |
| **节点图** | 见 `db/raw/channels.json` 的 `beyondInstructionGraphService`（create/delete/riskReport） |
| **资源** | 导入 · 导出 · 序列化 |
| **标签 / 套件** | 改标签 · 改套件 |
| **日志** | 导入 · 导入全部 · 删除 · 刷新报告 · 结束加载 |
| **性能** | 导入性能报告 |
| **音频** | 播放音乐 · 播放音效 |
| **仓库** | 打开资源管理器（按标签） |

**矩阵的空缺最值得注意**：实体侧有「改名 / 删除 / 聚焦 / 阵营 / 标签 / 挂图 / 删组件」，
**但没有「创建」和「移动/缩放」**——这不是本轮没找到，而是**操作名词表里根本没有这两个动词**
（`Create*` 只出现在节点图通道，`Move*` 只出现在快捷键的 `MOVE_NODE`/`MOVE_CANVAS`，都是前端画布语义）。
这与 `07-能力边界与缺口.md` 的结论一致：**创建与几何变换在当前前端命令面里没有对应词**。

## 四、与命令通道的对账

13 个通道 / ≥23 条命令（`db/raw/channels.json`）与本表的对应关系：

| 通道 | 对应本表的操作名 |
|---|---|
| `beyondEditObjService` | **11 条**：`DeleteEditObj`·`DeletePrefab`·`ModifyEditObjName`·`ModifyPrefabName`·`ModifyPrefabTag`·`FocusEditObj/Character/DropGather/Esp/Light/LocalBullet` |
| `beyondExportService` | `DoImport`·`DoExport`·`ImportDebugLog`·`ImportAllDebugLog`·`DeleteDebugLog`·`RefreshExistDebugLogReport` |
| `beyondInstructionGraphService` | create / delete / riskReport（**本表未捕获**——它们是通道侧词表） |
| `beyondPCGInstanceService` | 命令名**仅在字符串表，无派发调用点** |
| `beyondEffectService` | `focus`（小写，与 `FocusEditObj` 不是同一条） |
| `beyondAudioService` | `PlayMusic`·`Stop`·create·delete·modifyname |
| `wpfAudioService` / `wpfApplicationService` / `wpfInstructionGraphService` | **入站**服务，编辑器本地处理 |
| `beyondRoleStatusService` | 未观察到命令 |

**两处必须注意的差异：**

1. **命令通道的动词集比本表更大**——通道里有 `create` / `delete` / `modifyname` / `riskReport`
   / `Stop` 这些小写命令，本表的 camelCase 模式**抓不到它们**。说明**至少还有一整套小写命令词表**，
   量级未测。
2. **`beyondInstructionGraphService` 的 create/delete 是本工程实机调用成功过的**
   （建图：catalog 图资源 18→21），但它们在**本表里没有对应操作名**——进一步佐证第 1 点。
