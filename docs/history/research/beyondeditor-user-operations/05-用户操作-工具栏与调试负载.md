# 05 · 用户操作：工具栏、调试与负载检测

> **调查的问题：** 工具栏按钮、调试日志面板、负载检测面板各能让用户做什么？哪些通到游戏？
> **结论一句话：** 这三块共 **28 条操作**，**11 条直达后端** —— 也是「本地 vs 后端」分界最微妙的地方：
> 同一块面板里，纯视图按钮（缩放、折叠、快照）与发后端的按钮（跳到实体、导入日志）**挨着排**。
> 其中两条重要辨析：**「编辑器保存」不是「游戏原生保存」**；
> **负载检测面板是后端 9 条 `Focus*` 命令的唯一界面入口**。
> **可信度：静态。** 最后更新：2026-09-22

## 二、★ 辨析：「编辑器保存」不是「游戏原生保存」

**上一轮的表述需要修正。** 上一轮写：

> 「编辑器命令词汇里没有**保存**……`vmBtnSave*` 只是视图元素名」

**后半句不对。** `vmBtnSave` / `vmBtnSaveAs` 是**真的工具栏按钮**，中文文案就是
`UI_BEYOND_ASSIST_EDITOR_BLUEPRINT_SAVE` = **「保存」**、`_SAVE_AS` = **「另存为」**，
同族还有 `_SAVE_AS_TITLE` / `_SAVE_AS_NEW_NAME` / `_SAVE_AS_NEW_TAB` / `_SAVE_SUCCESS`。
用户确实能在编辑器里点「保存」和「另存为」，另存为还会弹框让输新名字并在**新页签**打开副本。

**真正成立的是后半段** —— 这个按钮**不发后端命令**：

| 检查项 | 结果 |
|---|---|
| `DoSave` / `DoExport` / `DoImport` / `SaveProject` / `SaveArchive` 在该类里 | **全部 0 命中** |
| `SaveFileDialog` / `OpenFileDialog` | **0** |
| `File.*` / `Directory.*` / `WriteAllBytes` / `WriteAllText` | **0** |
| `Http` / `Socket` / `Zip` / `Upload` | **0** |

**它有真实的保存动作**（不是空壳按钮）：`PLKaYuunsDIIyd0vEowZ.cs:444` → 画布 VM
`H4ENZduPkaQ5CTaa2ENJ.cs:4554`，中间做校验（`A8NrPMKmnpQkIiiyYetH.cs:2144`），
**校验失败弹「无法保存!」，成功弹「保存成功」**。

⇒ 最准确的表述是：**「有保存动作、没有直接的后端命令」**。
它保存的是**编辑器侧的节点图**，**与游戏原生保存写出的 GIL 是两件事**。

> 🔴 **2026-09-22 独立质量审查后的收口**：本节初版写「**完全不发后端**」，
> 并据此把它归为「仅本地」。**这个断言超出了静态证据边界。**
> 审查复核到的链条是：
> `PLKaYuunsDIIyd0vEowZ.cs:444`（保存处理器）→ 画布 `klquMJ8yGS2` →
> `H4ENZduPkaQ5CTaa2ENJ.cs:4554`（校验后构造消息 `uicix9H2RkA = 31`）→ `HveidOYukhu` →
> **`wBl9T6ixzIpeRsMBJbsW.cs:215` 按消息编号查订阅集合 → `:308` 调用订阅者 `FxPYUAMEUVc`**。
> **订阅者被调用，这不是效果的终点。**
> ⇒ 保存这一条的可达性已从「仅本地」改为 **「本地处理·同步未定」**：
> 能说的是「**没有直接的后端命令、没有文件对话框、没有文件 IO、没有网络调用**」，
> **不能**说的是「没有任何间接后端效果」。

> **这两件事在项目里长期被混淆**：
> - **编辑器保存** = 把节点图存进编辑器（本地）
> - **游戏原生保存** = `SaveCurrentLevel` 写出 `Beyond_Local_Save_Level/<关卡>.gil`
>   （由 `scene_cli.py save` 调用，已实测）
>
> 「用户在编辑器里点了保存」**不能推出**「游戏里有这个逻辑」或「存档已更新」。

## 六、音频试听的定性

`PlayMusic` / `PlaySoundEffect` 的正确表述：

| 维度 | 结论 |
|---|---|
| 前端**发给谁** | `beyondAudioService`（**不是** `wpfAudioService`） |
| 前端**发了没有** | ✅ 已确证（`EF8cLvuBwl2IuhblDnsY.JVFa9yuBBE11Zhdy7ce5.cs:224` / `:165`，10 个参数，callback=null） |
| 游戏侧**有没有处理器** | **判不了** —— 服务名查找走托管虚 `GetHashCode`，静态看不见 |
| 状态 | **`undecidable`**（**存在但没找到**），**不是「游戏不支持播放音乐」** |

> 上一轮曾有一个假设：「这两条可能发往 `wpfAudioService`（编辑器本地处理）」。
> **该假设不成立** —— 它们和 PlayMusic 同属 beyond 侧音频宿主类型 `EF8`。
