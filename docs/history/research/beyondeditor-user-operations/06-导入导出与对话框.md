# 06 · 导入导出与对话框

> **调查的问题：** 用户怎么把内容导入导出？对话框都有哪些？
> **结论一句话：** 导入导出只有 **`.gia` 一条通路**（`DoImport` / `DoExport`，后端读到的参数形状
> **与前端逐位一致**），另有 10 个 XAML 对话框与若干确认框。
> 其中 **`Template_Vector3Common`（三维向量输入框）是否发后端，是回答「能不能改已有实体变换」的关键**。
> **可信度：静态。** 最后更新：2026-09-22

---

## 一、导入导出：只有 `.gia` 一条通路

| 操作 | 前端入口 | 后端 | 落点 |
|---|---|---|---|
| **导出** | 对象右键 · 组 12；另有 `kg9jHSKBgsfObR2IXdPf.C6xKBZLdA0J()`（`SaveFileDialog` ×3，`*.gia` 过滤） | `DoExport` | `0x768d170` @`0x768d4d9` |
| **导入** | 对象右键 · 组 13；`EC9LaXKCud5dn7MZnrgl` 面板（`OpenFileDialog` ×3） | `DoImport` | `0x768d170` @`0x768d3c4` |

### 1.1 参数形状**两侧逐位一致**

| | 前端报的 | 后端读的 | 判定 |
|---|---|---|---|
| **DoImport** | `[uint index, bool, string, uint]` | `(int32[t1], bool[t3], string[t5], int32[t1])` | ✅ |
| **DoExport** | 6 元素 = 4×uint(t6) + 1×uint(t1) + 1×string(t5) | `(int32×4[t6], int32[t1], string[t5])` | ✅ |

**DoImport 比前端多一个实参**：第 6 参 = 协议 token，由传输层补上。

### 1.2 两条必须记住的限定

| 限定 | 说明 |
|---|---|
| **回执不是确认** | `DoExport` 的 39 份 `.reply.json` 证明回调**触发过**，但行数**恒为 `rows: []`** ⇒ 触发 ≠ 有内容 |
| **导入的 callback 是 null** | `DoImport` 的两条分支 callback 均 null ⇒ **连本地号票都没有** |

> 索引语义：游戏侧 `0xb49b820`（完整 141 B）是「数量边界检查 + `数组[index]`」
> ⇒ **索引是列表零基序号，不是场景 ID**。

## 三、★ `Template_Vector3Common`：位置 / 旋转 / 缩放的输入框

这是本轮最值得追的一个控件，因为**「用户能不能在编辑器里改已有实体的变换」**这个问题
的答案就落在它身上。

| 项 | 值 |
|---|---|
| Template | `Template_Vector3Common` |
| 实现类 | `UhbhJaK66RZ4wbVkn8IJ`（与 `Template_TextBoxCommon` / `Template_CheckBoxCommon` 同宿主） |
| XAML | 在 `BydeCustomControl` 的 `ControlCommon` 一带 |
| 绑定 | `vmX` / `vmY` / `vmZ` 三个字段 |
| 是否发后端 | **本轮未判定** |

**已知的相关事实（两侧拼起来）**：

1. 前端 39 条命令里**没有**任何位置/旋转/缩放的命令（发送器槽反查，见 `03-` §3.1）。
2. 后端两张分发表里**也没有**几何变换动词（`../beyondeditor-backend/` 已证）。
3. 项目既有实测：**「创建时传入变换参数」已通**（`scene_cli.py create --position --scale`），
   但 **「修改已有实体的变换」未验**（`HANDOFF-CREATE-SAVE-20260922.md` §1 明确说这是两项功能）。

⇒ **合理的推断（标 `inferred`，不是结论）**：`Template_Vector3Common` 改的是**编辑器侧的对象记录**，
要生效仍需走导入/挂载链路；但**本轮没有追到它的写回路径**，因此**不写成「仅本地」也不写成「直达后端」**。
