# 08 · 能力边界与缺口

> **调查的问题：** 这份「用户操作全表」能支持什么结论、不能支持什么？
> **结论一句话：** 它能回答「**编辑器界面上有哪些操作、每个操作落到哪段代码、有没有后端命令**」，
> 且是在**全语料单遍扫描**的意义上回答的。
> 它**不能**回答「运行时用户点下去会发生什么」—— 本轮**全部结论是 `static`**，
> 而且**没有一次实测是「鼠标真的点了菜单」**。
> **可信度：本节是对本轮结论适用范围的自我限定。** 最后更新：2026-09-22

---

## 一、能回答什么

| 问题 | 能答 | 依据 |
|---|---|---|
| 编辑器界面由什么构成？有哪些面板/对话框？ | ✅ | 48 个 XAML + 49 个 `Template_*`（`01-` `02-`） |
| 用户能点什么？ | ✅ | 253 个 `vm*` 控件，其中 66 个按钮（`db` 的 `ui_element` 表） |
| 有哪些输入方式？ | ✅ | 41 个输入事件词（含拖放/滚轮/双击/键盘） |
| 用户在每块功能上能做什么？ | ✅ | **92 条用户操作**（`03-`~`06-`） |
| 每个操作落到哪段代码？ | ✅ | 反编译注释 `/* -> Owner::Method */` |
| 每个操作有没有后端命令？ | ✅ | 类型引用图（13,445 条边）→ 命令宿主 |

## 二、不能回答什么

| 问题 | 为什么不能 |
|---|---|
| 用户点下去**运行时**会发生什么 | 本轮从未执行任何游戏/编辑器代码 |
| 菜单项的**实际显示顺序**与可见性 | 可见性由运行期条件决定（如 `CheckToggleButtonCanOpenMenu`），静态只读到构造 |
| XAML 里的**具体控件排布** | BAML 被加密，磁盘读不到 |
| 「复制对象」等 **2 条「未定」**操作的语义 | 现有证据不足（**不填默认值**） |
| `Template_Vector3Common` 改了之后**写回哪里** | 未追到写回路径 |
| 3 条 PCG 命令的**界面入口是否存在** | 两种解释无法裁决 |
| 编辑器里「保存」的**存储位置与格式** | 只知它没有直接后端命令、无文件对话框 |
| **图编辑/保存的后续同步链** | 消息总线订阅者 → 持久化/同步链**未追完**（`04-` §四） |
| 任何一个控件的**控件级命令** | 见「二点五」 |
| **17 个 `Template_*` 的**使用者 | 它们不通过那个访问器 getter 取名（分母 49，见 `00-` 信息缺口） |

## 二点五、`ui_element.backend_command` 为什么全表是 NULL

`db/userops.db` 的 `ui_element` 表里，**`backend_command` 全表为 NULL**。
这是**正确状态**，不是遗漏：

- 上游只做到「**这个类的文本里出现过哪些命令名**」= **类级共现**；
- 「**这个控件调用哪一条**」需要「事件处理器 → 具体命令」的完整链，**本轮一条都没追到**。
- 初版把「类里第一条命令」写给每个控件，于是造出 `vmBtnImportLog → DeleteDebugLog`、
  `vmBtnSnapShot → FocusScreenshot` 这类**假链**（独立质量审查发现）。

⇒ 现在类级候选命令存在 `class_candidate_commands` 列，明确标注为**候选**。
`build-db.py` 里有 `check_element_mapping()` 回归检查，四个已知反例必须保持 NULL。

| 3 | 「前端 44 条操作名里没有 `ApplyPrefabInstanceChange`」 | `../beyondeditor-backend/db/routes.json` | ❌ **错**。场景对象右键的「**应用**」就在发它；名字在前端是**折叠常量**不是字面量 |
| 4 | 「后端命令集 ⊋ 前端可触发命令集」 | `../beyondeditor-backend/00-总览.md` §②b | ⚠️ **需要收紧**：那 2 条在前端**都有入口**。本轮**没发现真正的差集** |
| 5 | 「PCG 服务命令仅字符串、无派发调用点」 | `../beyondeditor-frontend/05-` | ❌ **错**（上一轮后端已更正，本轮复核确认）：三条都有完整派发点 |
| 6 | 「新建文件夹是纯本地操作」 | **我自己本轮初稿** | ❌ **错**。资源树的新建文件夹**会发** `beyondeditorInstructionGraphService.create`；我最初在没追到发送点时默认填了「仅本地」，被子智能体纠正 |

> **第 1 与第 6 条都值得单独记住**：
> **第 1 条**是本项目第**四**次「用检索的缺失去证明不存在」，而且这次错在我自己上一轮。

> 而正确答案是「前端发了、后端没落点」。**默认值本身就是一个断言。**

## 四、三种「没有」，必须分开写

| 状态 | 含义 | 本轮实例 |
|---|---|---|
| **`disproved`** | 有**正面反证** | **1 条**：`EndLoadAllDebugLog` 不是下行命令（它是编辑器本地处理的入站命令） |
| **`not_found`** | 查不到，但**没有证据**说它不存在 | 3D 视口空白处菜单、PCG 的界面入口、13 个模板的使用者、`Template_Vector3Common` 的写回路径、快捷键字典能否编辑… |
| **`undecidable`** | 现有方法**判不了** | 音频两条、PCG 三条（服务名走托管虚 `GetHashCode`，静态看不见） |

> 本项目历史上四次严重错误都源自**用检索的缺失去证明不存在**。
> 本轮的措辞一律是「**在这个语料/这个编码下没有**」。

## 五点五、🔴 一条工具层面的陷阱（对全项目有效）

`.gitignore` 里有 `/.runtime/`。**Grep 工具会因此静默跳过整个目录**，
只回一句「No matches found」，**不告诉你目录被忽略了**。对照实验：

| 手段 | 同一目录 `.runtime/editor-catalog/resolved/` | 结果 |
|---|---|---|
| **Grep 工具** × `focus` | | **0 matches** |
| **bash `grep`** × `focuseditobj` | | **4 个文件命中** |

**本项目 12,375 个反编译 `.cs` 全在 `.runtime/` 下** ⇒
**用 Grep 工具在这个工程里查前端代码，永远查到 0。**

**后果**：任何基于 Grep 工具得出的「0 命中」结论都**必须复核**。
本轮与上一轮后端的**全量扫描都是 Python 直读磁盘，不受影响**；
但**前两轮若有靠 Grep 工具做的局部检索结论，需要重查**。
