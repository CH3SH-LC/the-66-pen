## 4. 每个接口的实验步骤与通过标准

每个接口建立实验卡，至少填写：稳定ID、来源/构建指纹、方向、业务目的、调用入口、参数及约束、依赖、对象作用域、风险、唯一请求ID、实验关卡/会话、预期变化、非目标不变量、恢复办法、实际证据和结论。事前意图沿用实验意图模板（历史来源：`../../offline-research/EXPERIMENT-INTENT-TEMPLATE.md`），字段缺失不靠运行时猜测。

1. **确认合同**：定位发送/接收或真实实现；判断同步/异步、返回值、回调、所有权、线程和前置条件。仅有字符串/比较点先列候选。
2. **准备基线**：核对当前身份、完整清单和只读基线；专用测试对象与可恢复副本就绪；只读接口也要记录数据来源和完整性。
3. **最小正例**：一次调用仅改变一个可明确观察的量；记录提交、实际执行、业务结果三个不同状态。
4. **独立读回**：由另一读取路径核对ID、属性、引用或事件；不能只回显请求、看ok=true或文件存在。
5. **持久与行为**：持久写入必须保存、正式文件差分、关卡重新加载核对；运行时节点必须有本次运行行为证据。瞬时焦点/音效等标明持久性不适用，并验证相应可见/可听效果。
6. **参数与失败**：有效边界、空值、类型错误、缺对象、错误目标/权限/模式；仅对已知可安全拒绝的输入做实机负例，畸形协议与未知原生参数先离线测试。
7. **重复与中断**：重复requestId、批量部分成功、超时、租约失效、迟到回调；先只读对账，再决定是否补发。通过适配层可控故障测试，不能通过杀游戏制造故障。
8. **清理与回归**：移除本次对象或采用已核验的恢复路线；核对非目标内容。失败定位到具体接口/字段，修正后重验受影响用例。

节点用例分两层：编辑器层测创建、常量、类型、连接、导出、保存；运行层测触发、输出、状态变化和副作用。泛型/列表/枚举按合同覆盖有区别的分支，不穷举无限数值组合。每个定义至少一个有效运行用例；确实只作编辑配置或仅特定模式可用者，说明依据及替代验收。不能用同类一个节点代替其余节点。

接收事件通过真实操作引发后观察，不能把主动调用接收器当端到端证明。焦点、截图、声音、调试工具也属于覆盖范围，按其目标效果验收；CU可用于辅助观察，不替代后台调用路径。

## 5. 状态、台账与覆盖率

计划的机器映射在coverage.json（历史来源：`coverage.json`），全部状态为planned；不会把历史通过记录重标成本轮通过。P00执行后新增逐接口台账和用例目录，以下是拟定结构，不是已经存在的实验结果：

- `registry.jsonl`：来源条目↔业务接口↔实际动作↔阶段↔用例，多对多映射；记录新发现和去重依据。
- `cases/<case-id>.json`：前置、输入、预期、断言、恢复、执行预算及负例设计。
- `.runtime/verification/interface-experiments/<build>/<run-id>/`：事前意图、基线、请求、回执、模型读回、文件前后副本、运行证据、清理与manifest。
- `results.jsonl`：追加式结果，不覆盖失败；另列未定位、合同待证、可试、运行通过、持久通过、行为通过、失败、阻塞、已证不适用。

每项按适用目标定义完成门槛：只读=可信且完整读回；持久写入=执行+模型+正式文件+重开；运行节点=编辑持久证据+行为；导出=完成回调+文件内容；多端=双方独立观测。人工触发/人工视觉证据明确署源，与自动验证分列。

看板分别报告来源归类率、合同确认率、实际试验率、目标验收通过率；节点、命令、业务能力、资源参数各自有分母，不能相加做一个虚假的总完成率。已证不适用要有依据并展示；阻塞和失败不能从分母消失。每批结束进行来源反向对账，新增接口及时入队。

## 6. 实验场景与调度

拟准备LAB-Core、LAB-Graph、LAB-UI、LAB-Combat、LAB-Coop等专用关卡或可恢复副本，名称仅为计划，不使用历史PID、关卡ID或旧审核文件作为当前目标。每个实验先核实际levelId；创建测试关卡接口未打通时，可在后续执行中由用户选择专用关卡，不能擅自将旧MVP变成试验场。

- 离线台账、反编译、schema/文件检查可以连续推进；实机前重新确认游戏/编辑器版本、权限、可用会话和租约。
- 不关闭、重启或接管用户游戏/编辑器IPC；必须重新启动游戏才能推进的步骤单独阻塞，其他离线工作继续。
- 真实写入串行，每批先一个最小实验，再根据耗时、可恢复性和剩余租约扩批；首次未知合同不批量试探。不同系统使用独立对象，失败不污染下一批。
- 任一版本/目标不符、基线不完整、出现非目标改动或结果不确定时，暂停对应写入链并做只读对账；不能盲重试或整档覆盖。
- 已有8小时helper、5分钟bridge、180秒探针是不同租约，历史期限不沿用；批次按实际剩余期限安排，不把续helper当续bridge。
- 当前用户仅要求计划书，实验从后续明确执行指令开始。本计划不创设额外逐项审批流程；执行授权明确后按其范围持续推进。对外发布仍依既有规则单独处理。
