# 06 · 出站方向 —— 游戏发给编辑器的消息

> **调查的问题：** 通信不是单向的。游戏侧**主动发给编辑器**的帧有哪些？谁发的、什么条件下发？
> **结论一句话：** **出站只有一个原语** —— `0xddef670(连接对象, 消息号, 载荷)`；
> 6 类实测观测到的入站帧里 **5 类**的发送者已定位到地址级（`1019` / `1020` / `1017` / `1011` / `3006`），
> 第 6 类（编号 `0`）**没有找到任何发送点**，但它的实测特征被量化到
> **严格 1 Hz 心跳**（租约秒数 == 入站次数，25 个 run 无一例外）。
> **可信度：静态 + 前端实测（含 1 处对 prior 工作的更正）。** 最后更新：2026-09-22

---

## 一、先分清两个方向，别把同一张表当两边用

| | 谁 **收** | 谁 **发** | 本轮证据 |
|---|---|---|---|
| **入站**（`0xa223420`，24 项，见 `05-`） | **游戏** | 编辑器 | ✅ 已解 |
| **出站**（本节） | **编辑器** | **游戏** | ✅ 5/6 已定位发送者 |

**同一批编号会在两个方向上都出现。** 例如 `1011` 既是游戏**接收**表里的一个处理器编号
（`0xa2236b4`），也是前端实测**收到过** 8 次的编号。
**不得**把入站表的目标地址当作出站发送点。

前端侧的观测口径（`packetKinds`）来自编辑器进程内的接收者列表遍历，
**只计入站帧**（上一轮用两个租约正面证明过：桥自己发出的 58 次 1018 计数为 `{}`）。
所以「前端实测到 N 次」= **游戏确实发了 N 次**。

## 二、出站原语：只有一条

| 项 | 值 |
|---|---|
| 函数 | **`0xddef670`**（242 B，`complete=true`） |
| 签名（静态） | `(rcx = 连接对象, edx = 消息号, r8 = 载荷)` |
| 下游 | `0xe937280`（限速 + 打时戳）→ **`0x80bbba0`（真实写帧）** |
| 连接对象来源 | 恒为 `[0x555fac8 + 0xfbf0]` —— **22 个调用者的 RIP 相对地址全部解析到同一个全局** |
| 另一条入口 | `0xe92ac60`：排空 `[conn+0x58]` 的**待发队列**（全动态，消息号不在立即数里） |

> ⚠️ **一个会让扫描漏判的写法**：多个发送者用**尾 `jmp 0xddef670`** 而不是 `call`。
> **E8-only 的调用者扫描会漏掉它们** —— `1011` 就是这样被漏掉的，
> 改用「扫 `mov dx/edx, imm` 立即数」才找回。本节的发送者清单是**两种扫法合并**的结果。

## 五、编号 `0`：没找到发送者，但特征被量化了

**这是本轮唯一一个连发送点都没有的编号，却是观测最多的一类（975 次）。**

| 证据 | 内容 |
|---|---|
| **频率** | **租约秒数 == 入站次数**：120 s → 120 次、25 → 25、3 → 3，**25 个 run 无例外** ⇒ **严格 1 Hz** |
| **帧内容** | 10 字节空包：`0656 0000 <上一个业务包的载荷长度> 0666` |
| **长度域的真相** | 那是**复用缓冲的陈旧值**（探针原始 hex 里直见 `17→17`、`33→33`）—— 不是本包的真实长度 |
| **扫描结果** | 全映像 `mov dx, 0` 候选 **2,972 处**，**没有一处**在 14 条指令内到达 `0xddef670` |
| **对称性** | **编辑器自己也发同形状的 `0` 包**（伴随 `1016`） |

⇒ 结论：**它是帧层的空包 / 保活帧，不属于任何已注册业务消息。**
**是「心跳」还是「空载荷写入」，从磁盘无法定论** —— 记 `undecidable`，不写成结论。

## 六、本轮更正 prior 工作的两处

| # | prior 说法 | 更正 | 依据 |
|---|---|---|---|
| 1 | `0x11d98fa0` / `0x11d99470` / `0x11d98d00` 是 **1020 的发送路径** | ❌ **不是**。它们**从不触及发送原语 `0xddef670`**；它们是 `0xbeaffe0` 状态机驱动的**外部资产记录摄取链**（接收方向） | 全函数扫描，无一处到达 `0xddef670` |
| 2 | 「1001 握手分支在 `0xa22353a`」 | ❌ **那是 `1020` 的发送调用点** | 同上 |

> **两处更正都指向同一个教训**：prior 工作当时是**按相邻性推断**的
> （「这个函数在附近，所以它是发送路径」）。
> 本轮有了「唯一发送原语」这个锚点之后，才能判「到不到得了发送点」。
> **结构性锚点比邻近性可靠。**
