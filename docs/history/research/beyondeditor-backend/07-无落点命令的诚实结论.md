# 07 · 无落点命令的诚实结论 —— 6 条命令的去向

> **调查的问题：** 前端 36 条业务命令里，有 6 条在游戏侧两张分发表里都找不到。
> 它们是**不存在**、**没找到**、还是**判不了**？
> **结论一句话：** **1 条 `disproved` + 5 条 `undecidable`，一条 `not_found` 都没有。**
> `EndLoadAllDebugLog` 被证伪为「不是下行命令」（它是**编辑器本地处理**的入站命令，
> 有正面反证）；其余 5 条（两条音频 + 三条 PCG）的**下行事实已确证**，
> 但「游戏侧有没有处理器」**机制上判不了** —— 因为服务名查找走**托管对象虚 `GetHashCode`**，
> 静态看不见。**6 条命令的四种编码在 `YuanShen.exe` 里全 0 命中**，
> 但这个「0 命中」**不构成任何否定结论**。
> **可信度：静态（反编译代码正面证据 + 全映像扫描）。** 最后更新：2026-09-22

---

## 一、先立规矩：为什么「搜不到」在这里几乎不说话

在给结论之前，必须先证明**「搜不到」这件事本身没有信息量**。三条对照：

| 对照 | 结果 | 说明 |
|---|---|---|
| exe 里搜**已知可用**的命令名 `DoImport` | **明文 ASCII / UTF-16 / UTF-8 全部 0 命中** | 它明明是活的命令 ⇒ **「没有明文」不可作判据** |
| exe 里搜已知服务名 `beyondExportService` | 四种编码 + 14 种哈希函数全 0 命中 | 同上 |
| `global-metadata.dat` 里搜 `GameObject` / `Service` / `mscorlib` / `System.String` | **全部 0 命中** | 该文件 **mhy 加密**（magic `0x4D485900` = `MHY\0`，标准 il2cpp 应为 `0xFAB11BAF`）⇒ **在这个文件上的 0 命中零信息量** |

**正向对照组（证明扫描器没坏）**：`FocusEditObj` 精确命中 `0x914e116`、
`ImportAllDebugLog` / `AddInstructionGraphForPrefab` / `DoImport` 均按预期命中，
哈希公式用 **9 个已知常量回代 9/9 一致**。

**另外，函数表上界 bug 的修正不影响本结论**：用不依赖函数表的
**734 处 cmp 型命中**做 RVA 邻域重聚类，两表结论不变
（RVA ≥ `0x10000000` 区间最大簇只有 3 个泛用名）。

## 二、`EndLoadAllDebugLog` —— **`disproved`**

**它根本不是下行命令。** 依据全部来自**可读的反编译代码**，不依赖任何字节检索：

| 证据 | 位置 |
|---|---|
| 字面量在 12,375 个反编译类型里**只出现在一个类** | `PSQ99ZKPMVVhBlIP6pR2.zll1ASKPPG90rdIZ1Ymn.cs` |
| line 85：作为**入站命令名比较** | 同上 |
| line 87：调用**该类自己的本地方法** | 同上 |
| line 200：该方法定义 | 同上 |
| 该类被注册进**编辑器本地服务表** | `resolved/tbLtNPi0Ktj7XmlZMWvt.CglXsi0ijgrwvs0SPGh.cs:144` |
| **没有任何一处是下行派发** | 全文扫描 `BrjMRrl2xRXv5aqZQkDJ.snthqqZ3HCR` / `Ikci0qkvMZX` 均无 |

**这是本轮唯一一条 `disproved`** —— 因为它有**正面反证**（在哪、怎么处置），
而不只是「找不到」。它是 **`ImportAllDebugLog` 的入站配对**：
后者在 `0x768d170` 有 FNV 分支，前者没有，因为它根本不该有。

> **配套核对**：`0x768d170` 里**没有第二比较链、没有小写别名** ——
> 1,803 字节全反汇编里 8 条哈希比较一一对应 7 个互异常量，
> `0x811c9dc5` 只出现 1 次。所以「它藏在别处」这个可能性已被排除。

## 三、其余 5 条 —— 全部 `undecidable`

| 命令 | 服务 | 下行事实 | 前端派发点 |
|---|---|---|---|
| `PlayMusic` | `beyondAudioService` (`boGLyQBJv9p`) | ✅ 已确证 | `resolved/EF8cLvuBwl2IuhblDnsW.JVFa9yuBBE11Zhdy7ce5.cs:224` |
| `PlaySoundEffect` | `beyondAudioService` (`boGLyQBJv9p`) | ✅ 已确证 | 同上 `:165`（私有实现 `ymCuByWOsnZ`） |
| `ModifyPCGInstanceName` | `beyondPCGInstanceService` (`Is6hqU640RJ`) | ✅ 已确证 | `resolved/mguq19iVCTpK600r3YtZ.Oe5aspiVGooyp47o5s0q.cs:12596` |
| `DeletePCGInstance` | 同上 | ✅ 已确证 | 同上 `:12601` |
| `FocusPCGInstance` | 同上 | ✅ 已确证 | 同上 `:12606` |

**参数形状（前端侧读出，非后端读回）：**

- `PlayMusic`：10 项 = `uint musicId` + `float×5` + `bool×3` + `uint`
- `PlaySoundEffect`：10 项 = `uint soundEffectId` + `float volume / playbackSpeed` +
  `bool isLoop` + `float loopInterval` + `bool enableAttenuation` +
  `float attenuationMaxDistance` + `uint attenuationType`
- PCG 三条：`[uint id]` / `[uint id, string name]`

### 为什么判不了 —— 是机制性的，不是没下功夫

**服务名查找走的是托管对象的虚 `GetHashCode`**：
`0x166f5370` 里 `mov rax, [key]; call qword ptr [rax+0xe0]`。
命令名则可能走**托管字典**的路。

⇒ **同一个二进制里就存在静态看不见的分发路径。**
所以对这 5 条，本轮的结论只能是**有界负面结论**：

> 「**在编译期常量哈希 switch 里没有分支**」

**不能**升级为「游戏不处理」。

### 搜索范围（支撑「判不了」这句话的边界）

对这 5 条，本轮扫过：

1. `YuanShen.exe`：**fnv1a 按 UTF-16 码元 / 4 种字节对齐**
2. `YuanShen.exe`：**30 个哈希变体常量**（小写 / 大写 / fnv1 / fnv1a-utf16 / utf16 字节序列…）
3. `YuanShen.exe`：ASCII / UTF-16LE / UTF-8 明文
4. `YuanShen.exe`：**734 处 cmp 型命中**的全映像重聚类（含 RVA ≥ `0x10000000` 区间）
5. `global-metadata.dat`：utf8 / utf16le / ascii（**该文件加密，此步零信息量，仅记录**）

**全部 0 命中。** 这个范围是这句话的唯一支撑 —— 换一个编码、换一个位置，
结论不适用。

## 四、本轮推翻的两条前端侧结论（必须记在账上）

| # | 前端侧的原文 | 本轮结论 | 依据 |
|---|---|---|---|
| 1 | `beyondPCGInstanceService` 的命令「**仅字符串，无派发调用点**」 | ❌ **错的** | 三条 PCG 命令**都有完整 1018 派发点**（`Oe5aspiVGooyp47o5s0q.cs:12596/12601/12606`），本轮已独立复核 |
| 2 | `create` / `delete` / `modifyname` 属 `beyondAudioService` | ❌ **归属写错** | 它们属 **`beyondInstructionGraphService`** |

**这两条一起指向同一个教训，而且它比结论本身更重要：**

> **前端侧的枚举是不可靠的 —— 它既会漏（PCG 有派发点被写成没有），也会错（服务归属写错）。**
> **「前端没写」不能推出「不存在」。**

这条在本轮被**正面证伪了一次**，不是抽象告诫。
后端侧本轮的结论之所以更硬，恰恰是因为它**不依赖前端那份枚举**：
它以**游戏映像的全量穷举**为准，前端清单只是用来做交集的输入之一。
