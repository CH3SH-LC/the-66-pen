## 0. 结论

1. **解码器确实有损**，原因不是"f2 谓词写错一个字"，而是**模板里有两条并列的组件块数组**：`f2`（实例）+ `f3`（类定义）。
   旧解码器只走 `f2`。
2. **正确规则**：`组件 = (E_f2 ∪ (D_f3 ∩ MajE[classId])) − {21}`，在 **192/192** 条可控预制体上与编辑器实读**逐条一致**
   （旧规则 190/192）。
3. **普查答案不变**：**没有任何预制体"启用"目标族组件**
   `{Collision=8, ClientTrigger=5, Intee=23, StuffBag=33, EquipStuffBag=34, Shop=35, Obstacle=41, Option=17, MpAction=24, Talk=28, CursorCollision=45}`。
   唯一非基线命中是 **`1000000 → PopUp=40`** 与 **`10007002 → DropGather=36`**（都不在目标族字面里）。
   **这次是 proof-grade 否定**（见 §5）。
4. 关键区分：`Collision=8 / ClientTrigger=5 / Option=17` **确实出现在 2611/2611/2727 条预制体的 `f3` 类定义数组里**
   —— 它们是"**该类支持但未启用**"的组件。旧文件里"一次都没出现"的说法会被误读为"读不到"；真相是"读得到、没启用"。

## 2. 规则怎么定出来的（不是调参）

- **`E_f2` 单独就是 190/192**：f2 块 = 该预制体显式启用（`f2=1`）的组件实例 —— 这才是主线。
- **`f3` 是"按 classId 近常数"的类定义/schema 数组**（1402 有 8 种变体，1172 条共用同一份）。
  它是"该类可用的组件全集"，**不是**该预制体的清单。
- 观察：`10003001` 实读多出的 `{1,3,19}` = `D_f3 ∩ MajE[1402]`，其中
  `MajE[classId]`＝该类**出现次数最多的 `E_f2` 集合**（即该类的"出厂标准组件集"）：
  `1402→{1,3,6,14,18,19}`（2602/2611）、`1405→{1,3,6,14,18,26,42}`（70/115）、`1401→{1,3}`、`1403→{1,3,40}`、`1404→其自身`。
- 于是 `组件 = E_f2 ∪ (D_f3 ∩ MajE[classId])`。**在 192 条可控集上 191/192**（唯一残差 = `1000001` 的 21）。
- `21 = TempAttachPoint`：**194 条实读清单里 0 次出现**，却出现在源码 1 条（`1000001` 的 f2）＋70 条（众数 f3）里
  ⇒ **编辑器侧就把它剔掉**，非字节层可表达。加 `− {21}` 后 **192/192**。

**同意数（vs 编辑器实读，192 条重叠）**

| 规则 | 逐条全等 |
|---|---:|
| v1 `E_f2`（旧） | **190/192** |
| `E_f2 ∪ (D_f3 ∩ MajE)` | **191/192** |
| v2 `E_f2 ∪ (D_f3 ∩ MajE) − {21}` | **192/192** |

v2 相对 v1 **只改动 4 条**（全部列在 §4）；其中 **`10003001` 是唯一有实读背书的**（f3 合并项被验证），
`1000001` 是去掉幻影 21（有实读背书），另两条（`10007002`/`10008001`）**无实读、属未控制外推**。

## 5. 目标族问题的 proof-grade 否定

问题：**是否有任何预制体随身携带 `{碰撞, 客户端触发器, 交互件, 背包, 商店, 选项, 额外碰撞}`

**答：零条。** 三条互不相同的路给出同一结论：

1. **(A) v1 f2-only 结构走查**，2729 条：0 命中。
2. **(B) v2 f2+f3 修正走查**，2729 条（本文件 §4）：0 命中。
3. **(C) 编辑器实读清单**（194 条）逐条核名串：0 命中，且 192 条重叠与 (B) 逐条全等。

**(1) 检索面已枚举**：`D:/games/.../OfficialPrefab/*.mihoyobin` 共 **2729** 个文件，
命令：`PYTHONIOENCODING=utf-8 python .runtime/scratch/prefab_component_census_v2.py`
（输出 `source files 2729 / decoded ok 2729 / decode errors 0`）。

**(2) 正对照（同一方法能找到东西）**：
- 同一读者**确实读得到目标 id**：`ClientTrigger=5` 出现在 **2611** 条、`Collision=8` 出现在 **2611** 条、
  `Option=17` 出现在 **2727** 条的 `f3` 块里（`.runtime/scratch/PREFAB-CENSUS-V2.json → prefabs[*].D_f3`）。
  故"0 命中"**不是**"读不到这些值"。
- 同一读者**浮出稀有非基线件**：`Enmity` 115、`MonsterAiComp` 70、`WaterCubeComp` 3、`WaterfallComp` 3、
  `PopUp` 1、`DropGather` 1 —— 若存在 `Collision/Shop/StuffBag` 启用块，不会静默漏掉。
- 同法在**真值**上 192/192 —— 方法端到端被地面真值验证。

**(3) 三条结构不同的路**：(A) 模板 `f2` 块结构走查（2729）；(B) 模板 `f2+f3` 双数组修正走查（2729）；

但**无实读对拍**；其否定强度依赖解码器在 192 条上 192/192 的正确性。
