> 本文件对账两个互斥的说法：
> - **旧说**（`NATIVE-ADD-COMPONENT.md` / `NATIVE-COMPONENT-CREATE.md`，以及引用它们的 `ADD-COMPONENT-MODEL-PATH.md`）：

## 0. 一句话结论

1. **两个说法不可能同时成立于同一映像。** 从**当前**二进制重新导出，**删除链操作的是 `[entity+0x68]`** ——
   这一点被 4 个互锁的函数（取/建/建或取/收尾）**逐条**证实（§2、§3）。
2. **`[entity+0x48]` 不是错在偏移，而是错在「对象」**：它来自另一个函数（`0x10aa6800`，一张**按 key 查的映射**访问器），
   该函数**不在删除链上**，旧文档把它当成了「实体组件容器」（§4）。
3. **更根本的一层**：旧说的**整片地址空间**（`0x914de40 / 0xcb64140 / 0x10abeb40 / 0x10ac50a0 / 0x102d4750 / 0x10aa6800 / 0x914ccd0`）
   **全部来自一份更旧的 `YuanShen.exe`**，**在当前二进制里一个都不是函数起点**（§1）。**旧文档过期了，不是写错了偏移。**

**判决：错的是 `NATIVE-ADD-COMPONENT.md` 与 `NATIVE-COMPONENT-CREATE.md`（及照抄其地址的 `ADD-COMPONENT-MODEL-PATH.md` §：86）。**
错法有**两层**：(a) **拿了一份 Sep-22 的旧映像的地址**（当时游戏尚未更新），(b) 在旧映像里**误把「映射访问器 `0x10aa6800`」认成「实体组件容器」**。

## 4. 那 `[entity+0x48]` 是什么？——**另一个对象，且是另一条链**

旧文档的 `[entity+0x48]` 唯一出处是 `0x10aa6800`（`NATIVE-ADD-COMPONENT.md` §3 #1 / §4.4；`ADD-COMPONENT-MODEL-PATH.md:86`）：


（原始代码或现场命令片段未随公共研究笔记分发；可用工具见目录。）


**这是「按 key 查的映射」访问器**（`IndexOf` + 24 B 元素），与删除链的 `[entity+0x68]`（**指针列表**，步长 8）
**结构不同**（24 B 内联 vs 8 B 指针）。它在旧文档里被用于 **AddInstructionGraph 路径**（取「第 3 号组件」），
**从来不在删除链上**。旧文档把这条**旁路访问器**当成了「实体组件容器」，再把它推广到删除链——**这是「对象认错」**。

在**当前**二进制里，同一个「`[obj+0x48]` 映射访问器」形态仍在（11 个同形态候选，如 `0xadfd840` 217B、`0xd1d7de0` 227B，
都含 `mov rdi,[rdi+0x48]` + `lea rax,[rax+rax*2]; mov rax,[rcx+rax*8+0x30]`）——即 **`+0x48` 这个字段本身是「另一族」的，
与组件列表并存的可能是「某种按 key 索引的注册表」**。**本文件不断言它到底是什么**；只断言：
**它不是删除链/创建链使用的组件容器**，且旧文档引用的那个**具体地址 `0x10aa6800` 在当前二进制里已失效**。

## 6. 更正后的**单一一致**账目

1. **组件容器**：实体上的组件是**指针列表** `entity[+0x68]`：内层 `+0x10`=数组基址、`+0x18`=count、`+0x1c`=版本号；
   数组元素步长 **8**，元素是**组件对象指针**。
2. **组件对象**：`comp[+0x20]`=owner entity、`comp[+0x28]`=type/config、`comp[+0x30]`=**byte**(enabled)、
   `comp[+0x34]`=**int32 kind**。
3. **attach 对**：**建** = `0x867c610`（`0x867d2c0` 建或取）；**取** = `0x867cc80`；**删** = `0x97e97d0`
   （取→`comp[+0x34]==0x15` 特判 `0x8678700`→注销 `0x107ac000`→收尾 `0x867b170`）。
   **建/取/删共用同一 `entity[+0x68]` 与同一 `comp[+0x34]`** —— **这就是「加」的落点**（建时插入，与 transform 同一手法）。
4. **`+0x15` 特判**：`comp[+0x34]==0x15` 是**某个 kind**；是否等于前端枚举 `21 TempAttachPoint` **仍未证**（沿用旧口径，本文不声称）。
5. **安全边界（供后续 native 设计用，本文件不执行任何调用）**：`0x867c610` 首条实体访问是 `mov rcx,[rsi+0x30]; test; je 0x4b9c60`，
   并在 `0x867c6dd` 读 `[rsi+0x68]`。⇒ 任何 native 调用的**守卫必须拒绝 `entity == NULL`**（越界即空引用），
   且须保证实体 `[+0x30]` 子对象非空。**「拒绝非空 owner」式的反向守卫是 fail-open，必须反过来写。**
