## 0. 一句话结论

**牌子（告示牌 / 提示牌）不是「零资产 · 玩家可见文本」通道。** 三条独立的负结论合围：

1. **没有任何节点能把文本写到实体上。** 全 810 条定义里，与「文本」有关的节点只有 8 个（§2）；
   其中**唯一能在世界内实体上显示文本的两族——`631 切换生效的文本气泡`（= 任务里的「267」）与
   `615/616/617 铭牌`——入参都是 `配置ID`（合同里类型码 `1`＝配置引用），不是字符串**。
   它们**只在一个「编辑器里手工配好的文本列表」里选生效项**，不写入任意文本。
   仓内**不存在**「目标实体 + 字符串 → 显示」这种形状的节点（§2.3 用 69 条 string-input 节点反证）。
2. **牌子 prefab 是否自带文本组件——无证据，且反向证据更多。**
   预制目录（2722 条）只存名字/图标，不含组件（§3.1）；能读「预制默认组件集」的深读回执
   `prefab-fields-page` 只覆盖 **194/2722** 个预制，**告示牌不在其中**（§3.2）；
   在那 194 个里 `BeyondCompTypeTalk`（文本气泡组件）出现 **0** 次。
   官方语料里**没有任何一章**提到告示牌 / 提示牌 / 招牌 / 指示牌（§3.3）。
3. **即便牌子真带了文本组件，也仍然要「预置资产」**：气泡的**文本内容**与**配置ID**都是
   **编辑器「添加组件 → 详细编辑」里手工写出来**的（`mhwtz297kp6a`），
   而「给实体加组件」在本工程**已证不存在**（`CLAUDE.md` §六(a)）。

⇒ **最省的玩家可见通道，仍然不是牌子，而是 presentation 家族的 `308 激活/关闭模型显示`**
（与 `VISIBLE-NO-ASSET.md` §5 的冠军一致）。牌子唯一能零资产做到的，是**像任何实体一样**
被 `308` 显示/隐藏、被 `835` 改色——**那与「牌子」无关，且都不是文字**。

## 4. 判决

**问：世界牌子是不是「零授权资产、玩家可见文本」的通道？**

**答：不是。** 依据：

1. **上游（写入端）不存在**：没有任何节点把文本写到实体上（§2.3，全 69 条 string-input 节点逐条排除）。
   唯一在世界内实体上显示文本的两族（文本气泡 631、铭牌 615/616/617）**入参是 `配置ID`**，
   只能在**编辑器里手工配好的文本列表**里切换生效项，**不写任意文本**（§2.2）。
2. **中游（宿主端）也不成立**：文本气泡/铭牌都是**通用组件**，需要「添加组件」——
   而「给实体加组件」**已证不存在**（`CLAUDE.md` §六(a)；`PREFAB-COMPONENT-WRITE` 亦证预制体侧同样加不了）。
   文本内容与配置 ID 都**只在编辑器 UI 里生成**（`mhwtz297kp6a` / `mh5n160t2b6w`）。
3. **牌子 prefab 的「默认文本面」无证据**：预制目录/回执不含组件；194 个有组件回执的预制里**没有牌子**、
   `Talk` 计数为 0；官方语料里没有任何牌子章节（§3）。牌子是**烘焙贴图的美术道具**。
4. **牌子能零资产做到的，与「牌子」无关**：把 `308 激活/关闭模型显示` / `266 屏幕震动` / `835 改色`
   接到**任何**实体上都成立，牌子不构成特殊待遇，且**这些都不是文字**。

**⇒ 最省的「玩家看得见」通道，仍然是 `308 激活/关闭模型显示`**（`VISIBLE-NO-ASSET.md` §5 的冠军）：
只需一个**已能建的动态实体** + 一个布尔，**零新资产**，且**不进模板/组件/UI 三条已证封死的路**。
牌子在这条冠军旁边**不提供任何额外能力**——它和「通常立方体」在能力上是同一档。

**⇒ 结论一句话**：**别把 demo 的可见性赌在牌子上。** 要「让玩家看见」，走 presentation 家族；
要「让玩家读一句自定义文字」，本仓当前**没有原语**（`VISIBLE-NO-ASSET.md:31-35` 同判）。
