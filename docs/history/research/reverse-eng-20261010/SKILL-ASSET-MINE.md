## 0. 一句话结论（判决前置）

**技能力是「编辑器资产模板」的同一类东西**——它是 **ID 类型表里的一等公民**（配置ID 类型 `6 = 自定义技能`、
`28 = 造物技能`、`37 = 角色操纵技能`，`mhsd6lrx3voe.json:64`），与 `10 = 资源货币` / `8 = 普通道具、装备道具`
**共用同一张「配置ID」类型表、同一套 32 位分段 ID 规则、同一个「UI 里点【新建…】按钮自动生成配置ID」的创建手势**。

**⇒ 技能创建卡的是「同一条缺失原语」——「没有任何写入面能建出一个带配置ID 的编辑器资产」**，
**不是**另一套独立子系统的另一个问题。今天约束货币/道具/商店/职业/单位状态/技能的是**同一堵墙**；
一旦「建编辑器资产模板（把一条带类型化 id 的记录写进 `.gil root field 15`）」这条原语打通，
**技能创建也一起解锁**（但技能另有「技能动画 / 事件轨道 / 槽位绑定」这几层**同一面板内**的附加写面，
见 §4 的 caveat）。

分三层写清（`CLAUDE.md:25`）：**文档写了什么 / 工具能做什么 / 真机验证过什么**——§5 单列。

## 2. 技能资产 = 和货币/道具模板同一种东西吗？（问 2）

**答：是同一种「带配置ID 的编辑器资产」，只是分属不同的编辑模块家族；不是另一套子系统。** 依据（逐字句对照）：

| 维度 | 货币 / 道具（资源系统族） | 技能（战斗预设族） | 是否同构 |

**一处必须点破的边界（否则会过度概括）**：
- **UI 归属不同家族**：`mhexhcr1qjh2.json:18` 的「战斗预设」五模块里**有「道具」但没有「货币」**；货币/背包/商店
  走的是**系统菜单【货币与背包】/【商店模板管理】**（`mh2cr30yeak0.json:26`、`mhi9s7isvp50.json:62`、`mhogfq9bf86q.json:32`）。
  ⇒ 技能与**道具**在**同一 UI 模块（战斗预设）**里；技能与**货币**分属不同 UI 模块，**但共用同一张配置ID 类型表**。
- **doc 分类**也不同：技能挂 `高级概念` 直下，货币/道具/商店/背包挂 `高级概念 / 资源系统`（见 §1 表 hierarchy 列）。
  doc 的树是**概念分类**，不是**数据模型**；数据模型上它们同表同段。
- **技能是「复合资产」，货币/道具是「叶子模板」**：技能内含 **技能动画（资产）** + **事件轨道/状态轨道** +
  可挂 **技能节点图**（`mho81frl33im` facts 14–16、`mhlgj60615uw`、`mh57xz9afh7e`）。
  货币/道具模板只有扁平字段。**⇒ 同类不同复杂度**（这影响 §4 的 caveat）。

**⇒ 第 2 问答案**：技能是 **「编辑器资产 + 配置ID」这一 KIND**（与货币/道具/商店/职业/单位状态同族），
**不是**另一个子系统；差别只在「UI 挂在哪个模块」与「内部结构复杂度」。

「战斗预设 = 0 命中」「主编辑器外壳的中文界文本不在本批资源内……很可能封装在加密的 `assets.bin`」）。
这**同时**解释了「为什么命令面里既没有建技能、也没有建货币的入口」——**因为那两块 UI 根本不在已逆向的语料里。**

### 4.2 结论句

> **技能创建卡的原语，与货币/道具/商店/职业/单位状态创建卡的是同一条**：
> **「把一个带类型化配置ID 的编辑器资产记录新建出来」这条写路径不存在**。
> 它们**共用**：同一张配置ID 类型表（`mhsd6lrx3voe.json:64`）、同一套「UI 新建按钮 + 弹窗确认」的手势、
> 同一块未被逆向的编辑器面板、同一个候选磁盘落点 `.gil root field 15`。
> **⇒ 打通「建编辑器资产模板」这条原语，会一并解开技能创建**（以及货币/道具/商店/职业/单位状态）。

### 4.3 caveat（必须写明，否则会过度承诺）

即使「建资产」原语打通，**技能比货币/道具多出三层写面**，它们都在**同一块技能面板内**、因此**同乘一条路**，但仍是额外要落地的字段：
1. **技能动画引用**——技能持有「动画资源 / 所在栏位 / 动画时长 / 栏位时长」（`mho81frl33im` facts 17–18），
   动画本身是**独立资产**（`mh57xz9afh7e`）。⇒ 需「引用的动画资产已存在 + 能写进技能的槽位」。
2. **事件轨道 / 状态轨道**——四类事件轨道（开始/结束/节点图/状态）+ 循环节 + 分支轨道（`mho81frl33im` facts 15–24）；
   造物侧还有「事件轴总长 = 所有动画时长之和」的尺度契约（`mhftoirpwd46` fact[11]）。
3. **挂到单位上才生效**——技能实例要**绑定槽位**才可由玩家输入释放（`mho81frl33im` fact[31]，
   `mho81frl33im.json:210`）；槽位映射「普攻=左键 / 技能1=E / 技能2=Q / 技能3=R / 技能4=T」，
   空中技能槽在「战斗预设-玩家-职业-技能配置」新增（`mho81frl33im` facts 28,30）。
   节点图侧**只能按配置ID 引用**技能（`data/node-contracts/variants/server/bucket-*.json` 的端口名「**技能配置ID**」，
   如 `bucket-00.json:4652`；节点 395/397/806/809/816/817 等入参即此），**不能造技能**。

⇒ 一句话：**「建资产」是必要且共用的一步；技能另有『动画 + 轨道 + 槽位绑定』三小步，但它们都在同一面板内，
不是新的墙。**
