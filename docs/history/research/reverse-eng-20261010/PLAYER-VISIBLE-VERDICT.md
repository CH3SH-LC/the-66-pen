## 4. 对 demo 的诚实后果：造了第 1 名，玩家会看到什么

**现状**：当前已真机的 15 节点 demo 图（`.runtime/scratch/MW_API_FARM_DEMO-plan.json`，节点序含 `92`×2、
`686`×3、`733/690/233/2/702/701/688/684/1`）里，唯一「输出」是 `1 打印字符串`（`values` 段里
`"材料不足"`）——**玩家什么都看不到**，只有开编辑器日志的人看得到。这就是「为什么现在 demo 是瞎的」。

**若把第 1 名（308）接到已通管线上**，玩家会看到——

1. **一个我们建的动态实体，在关卡加载（`71 实体创建时`）或玩家触达（`92 进入碰撞触发器时`）时，
   其模型出现 / 消失**。除此之外**什么都不变**：没有文字、没有 HUD、没有 UI 元素、没有音效、没有震动。
2. **最可能的失败模式是「静默」**：如果 308 的逆推语义有误（例如它只对布景/静态实体生效，或该 server 节点被驳回），
   **不会有报错、不会有提示**——玩家看到的是「和没加一样」。所以这条实验的判据是
   **「模型是否真的消失/出现」**，而不是「图有没有建成」。
3. **还有一个与节点语义无关的失败模式：实体不在视野里**。出生点是玩家模板上的预设点、落点＝关卡原点
   （记忆 `spawn-point-is-a-player-template-field`），所以「建在原点附近」并不保证在玩家开场视野内。
   → 用 `92 进入碰撞触发器时` 触发、把实体放在玩家必经处，比 `71 实体创建时` 更稳。

**一句话**：造第 1 名，玩家**最可能**看到「一个方块凭空出现/消失」；**最坏情况**是什么都没变（而图确实在跑）。
