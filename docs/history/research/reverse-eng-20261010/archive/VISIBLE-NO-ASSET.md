## 0. 一句话结论

1. 用题给关键词（`提示/气泡/消息/界面/显示/播放/特效/飘字/标牌`）在 **500** 条服务端合同里命中 **21** 个节点。按「入参是否引用一份预置资产」分三类：
   - **13 个直接吃一份资产/配置ID**（`93/94 特效资产`、`473 特效资产`、`594/598 音效资产索引`、
     `631 文本气泡配置ID`、`382 布局索引`、`383/384/521 控件组索引`、`827 动效控件索引`、
     `833 消息队列索引`、`856 礼盒索引`）——**我们在编辑器里造不出来**；
   - **4 个只吃上一类产出的句柄/序号**（`95 特效实例ID`、`591/592/593 音效播放器序号`）——
     句柄本身不是资产，但拿不到它，节点等于空转，仍**依附于资产**；
   - **4 个入参不看资产**（`308`、`316 界面控件组触发时`、`317 获取玩家当前界面布局`、`679 文本气泡完成时`），
     但其中 **316/679 只是事件（纯输出）、317 只是读取（纯输出索引）——三者本身都不产生可见效果**。
   **因此 21 个里「零资产、且自身直接产生可见效果」的只有一个 = `308 激活/关闭模型显示`。**
2. 题给词表之外，本文件另扫出同族可见节点（`镜头/震动/光标/光源/颜色/材质/模型显示/选项卡/小地图/悬浮/卡牌`）。
   其中 **`266 激活屏幕震动`** 与 **`835 修改模型颜色和材质`** 同属**零新资产**通道。
3. **「最少新资产」冠军 = `308 激活/关闭模型显示`（定义 id 308）**：
   入参只有 `目标实体` + `是否激活`（布尔）。**不要任何资产、任何配置ID、任何格式约定**。
   把它接到我们**已经能建、已经能绑图**的动态实体上，切换这个布尔＝该实体模型在玩家眼前出现/消失。
   这是当前逆向水平下**唯一同时满足「零资产」+「落在已通真机管线上」+「二进制、不可能看错」**的通道。
4. **诚实的负结论**：**没有任何「文字」通道是零资产的**。所有能显示字的入口——
   文本框（需界面布局+控件组）、`631 切换生效的文本气泡`（需组件+文本气泡配置ID）、
   `615/617 铭牌`（需组件+铭牌配置ID）、`833 更新消息队列`（需界面布局里的消息队列控件）——
   **全部要一份编辑器里手工搭好、我们无法通过桥创建的资产/组件**。
   要「向玩家显示一句自定义文字」，本仓当前**没有**原语。
5. 因此本题的答案**不是**「每个可见通道都要资产」；**是**：**可见的通道分两层——
   几何层（隐藏/显示模型、震动、改色）零资产可用；文字/UI 层全部要资产。**

## 1. 方法与口径

- **词表命中**：对 500 条合同逐条取 `name`，按题给 9 个词做子串匹配 → 21 条（§2 全表）。
- **扩展命中**：另按 `镜头/震动/光标/光源/颜色/材质/模型显示/选项卡/小地图/悬浮/卡牌/铭牌` 扫同一批 500 条
  （这些词**不在**题给词表内，但节点效果同属「表现而非改状态」）→ §4。
- **每条 pin 读法**：从合同 `ports[]` 逐 pin 读 `kind`（exec/data）、`direction`（in/out）、
  `name.value`（记名）与 `valueTypeNameRaw`（记数，0＝未记/None）。数值型别码经
  `data/node-contracts/shared/value-type-codes.json` 的历史推断表解读（该表**自标为「project-inference / 7.0-era」**，
  故本文写「码 6（推断：布尔/枚举/类型）」这类带层级的措辞）。
- **资产判定**：一个节点算「零新资产」当且仅当它**只吃**（a）我们能建/能拿的**实体或玩家引用**、
  （b）**标量/布尔/向量/枚举**值。凡是吃 **配置ID / 资产索引 / 布局索引 / 控件组索引 / 组件序号**的，
  一律算「要预置资产」。
- **官方对账**：每个候选给出 `docs/official-docs/chapters/<pathId>.json` 里**逐字**说了它什么（或「无章」）。
- **三层口径（CLAUDE.md §一.3）**：本文谈的几乎全是 ① 文档写了什么 与 ② 工具能做什么；
  **③ 真机验证过什么 = 无**（§6）。

## 3. 每个候选的资产判定（要资产 / 不要资产）

### 3.1 零新资产（作用在纯实体/纯玩家上）

**308 激活/关闭模型显示** — `目标实体` + `是否激活`（布尔）。
两入参**没有一个是资产引用**：一个是实体，一个是布尔。官方知识库**没有任何一章**点名该节点本身
（全 201 章文本检索「模型显示」只命中 `mhnffmieeqbg 实体摆放`，而那是**页签/可见性概念**、不是这个节点）；
但该章 `mhnffmieeqbg.json:161` 有一条**同族旁证**可用：「模型可见性仅影响模型显示，不影响实体上的其他逻辑」——
即「模型显示」在官方口径里是一个**独立于实体逻辑的纯表现开关**，这支持本节点「切布尔只改看不看得见」的读法。
语义因此**主要由节点名＋pin 名得出**：切换布尔＝目标实体模型显示开/关。
`docs/editor-catalog/NODE-CATALOG.md:831` 记它 `入×1，出×1`、参数 `是否激活、目标实体`、类别码 4。
**判定：零新资产，可直接落在我们已建成的动态实体上。**

**266 激活屏幕震动** — `玩家实体列表` + `震幅` + `震动时长` + `震源距离`。
四入参全是标量，**无资产引用**。无官方章（全章检索「屏幕震动」0 命中）。
`NODE-CATALOG.md:792` 记参数 `震幅、震动时长、震源距离、玩家实体列表`。
**判定：零新资产，连实体都不需要，只给玩家。** 可见性＝镜头抖动（§6 有保留）。

**835 修改模型颜色和材质** — `目标实体` + `是否覆写颜色配置`(bool) + `是否启用自定义颜色`(bool) +
`填充颜色` + `颜色透明度` + `颜色叠加类型`(枚举) + `是否覆写材质配置`(bool) + `是否启用自定义材质`(bool) +
`填充材质类型`(枚举)。**没有一个是资产引用**：颜色是数值码、透明度是 0–100 整数、材质是引擎自带枚举。
官方对账（`mhrutdio6904 模型`，逐字）：`mhrutdio6904.json:104`
「节点【修改模型颜色和材质】中的【颜色透明度】参数，取值范围也为 0-100 的整数…向下取整」；
同章枚举「可选冰材质和石化材质」「覆盖：自定义颜色将完全替换实体或物件的原生颜色 / 正片叠底：自定义颜色将叠加在原生颜色上」。
`NODE-CATALOG.md:1130` 记其 10 个输入参数与 `入×1，出×1`。
**判定：零新资产**（唯一格式不确定项是「节点图颜色码」的进制——章内只说「10 进制代码」、
不给与 rgba/hex 的关系，`mhrutdio6904` 的 notSay 明列此缺口；故颜色值需一次试错，但**不涉及资产**）。

## 5. 排行：最少新资产 → 冠军

| 名次 | 节点 | 需资产 | 需我们建东西吗 | 可见性 | 真机证据 |
|---|---|---|---|---|---|
| **1** | **308 激活/关闭模型显示** | **0** | 只需一个**已能建的动态实体** | **二进制**（实体模型出现/消失，不可能看错） | 无（节点级） |
| 2 | 266 激活屏幕震动 | 0 | 只需**玩家**，连实体都不要 | 镜头抖动（幅度/时长可调，可能被玩家忽略） | 无 |
| 3 | 835 修改模型颜色和材质 | 0 | 一个**动态实体** | 实体变色/加冰·石化材质（颜色码格式有 1 处文档缺口） | 无 |
| 4 | 846–848 玩家光标 | 0 | 玩家 | 弱（HUD 光标策略，不是「反馈一句」） | 无 |
| 5+ | 特效/音效/文字/界面/铭牌/礼盒族 | **1 份资产** | 桥造不出 | 强（正是我们要的「看得出来/读得到」） | 无 |

**冠军＝`308 激活/关闭模型显示`。** 理由：
(a) **零资产**；(b) 只需要**我们已能建、已能绑图的动态实体**（真机闭环已通，见 CLAUDE.md §五）；
(c) 反馈是**二元且不可误读**（模型有/无），比「震动」更硬、比「改色」少一个格式缺口；
(d) 触发也现成：`71 实体创建时`（`data/node-contracts/variants/server/bucket-07.json:1169`）驱动一次即可，无需任何 UI。

> 「给玩家看 ANYTHING」的**唯一现成答案**：在玩家出生点附近建一个可见动态实体，
> 挂一张 `实体创建时 → 308 激活/关闭模型显示(目标实体=自身, 是否激活=false/true)` 的图，
> 让它在关卡加载时出现或消失。**看得见，且一张资产都不新增。**

## 6. 诚实边界（不许越界的三条）

1. **先分清三层**：本文全部是 **① 文档写了什么**（官方章）＋ **② 工具能做什么**（合同/NODE-CATALOG）。
   **③ 真机『玩家真的看到了』＝ 0 条**。308/266/835 没有一条经过「建实体→绑图→原生 save→进游戏目视」的验证。
   把它们写进结论时必须带「candidate，未真机」这半句。
2. **「进了模型≠看得见≠能玩」**（MEMORY / doctrine）：本文只论证了**节点参数面不需要资产**——
   没有论证「这些节点在服务端图里真能被求值」「求值后真产生可见帧」。
   `308` 与 `266` **连官方章都没有**，其语义是**由节点名+pin 名逆推**的，属②层弱证据。
3. **代码/UI 侧的硬边界未跨**：CLAUDE.md §五/§六已证**写 UI、加组件、加模板、改 transform 全无原语**。
   本文件的排序正是**承认**这条边界后的产物——它把「可见反馈」从「要资产」的那半，**挪到**了
   「纯几何」的那半，而不是假装我们能造 UI 资产。
4. **反例对账**：当前的盲通道 `1 打印字符串`（`bucket-03.json:7`，pin 仅 `字符串{in}`）**零资产也没用**——
   官方 `mhu951iz7wz8.json:16/56`逐字：它的输出只进「窗口——日志 → 节点图日志窗口」里的**「打印信息」字段**，
   且**只在关卡运行且该图被『节点图筛选页签』筛中**时才返回。**它是编辑器调试通道，不是玩家可见通道。**
   这解释了「为什么现在 demo 是瞎的」：我们用的是唯一一条**既零资产、又不给玩家看**的节点。
