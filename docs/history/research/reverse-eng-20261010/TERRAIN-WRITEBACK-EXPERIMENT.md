三点读数，都直接支撑后面的设计：

1. **改动是可定位的单字节**：`cell(x,y)` 编码为 `f4{ f1=(x<<16)|y, f2=value }`，值 `1→2` 是 varint 的

3. **可用的对照锚**：**默认地形的 field-7 sha = `1c9d2287d86fbd98`**（15 个带 field 7 的关卡**全部相同**，

## 二、实验范围（只回答一个问题，别的都别问）

**唯一目标问题（Q）**：当**写入方未持有**某关卡时，我们把改过的 field 7 写到磁盘上，
**下一次打开该关卡**时，写入方是**从磁盘重读**（我们的改动存活）还是**从别处（如运行时缓存）覆盖**（改动消失）？

**明确排除、不做的事**：

- **不测"持有态写回"**——已由 `TERRAIN-WRITE-RISK.md` §3.1 判为**会被覆盖**，重测只是浪费一次真存档。
- **不测 `add_terrain`（给占位关卡加第一块地形）**——那是**新增整个 field 7**，改动面比"改一格"大得多、
  更难回退；等 Q 有答案后，若还需要，再单独立项。
- **不测"运行中的游戏即时看到新地形"**——`terrain.py` 没有这条路径，写入方也不会在持有期重读，别做。

## 三、目标关卡选择（"最不重要的那一个"）

**判据（按重要度降序）**：① 名字/用途明显是测试或占位；② 体积小（含损失面小）；③ 带默认 field 7（保证走"改一格"而非"加地形"）；④ 不是用户活档；⑤ **用户亲自确认**。

- **目标关卡 T：`1073741838`「实例摆放测试」**（16007 B，带默认 field 7）。
  理由：**它的名字自己声明了这是测试关卡**（"实例摆放测试"），体积小，含默认地形；即便整关报废，
  用户损失的是一块可重建的测试场地。**不是**活档（活档是 `1073741842`，见 §1.4）。
- **对照关卡 C：`1073741829`「自定义页签_1_存档_2」**（16026 B，带默认 field 7）。
  作用：**同一次实验里也写它、但从不打开它**——若 T 被覆盖而 C 存活，"是否被持有"就是自变量，结论才干净
  （这是 `TERRAIN-WRITE-RISK.md` §5 E2 第 6 步的负对照）。C 同样选小体积、自动命名的默认存档。

**不要选**：
- `1073741842`（活档，正在被追加 field 6）、`1073741840/841`「第66.x的笔_存档」（最大、看着像真实作品）、
  `1073741835`（148 KB）——价值高，排除。
- **占位关卡 `1073741826/827/836/837`**（78-95 B，**无 field 7**）——虽然"最没内容"，但它们走的是
  `add_terrain` 路径（新增 field），**改动面更大且更难回退**，与 §2 的"只改一格"范围冲突，排除。

> **STOP-0（用户确认）**：T 与 C 的选择**由用户最终拍板**——"哪关最不重要"是用户的判断，不是工具的。

## 四、实验序列（带显式 STOP 点）

> 全部步骤**在获得 §5 前置条件与 STOP-0 批准之前不得开始**。每个 STOP 是**弃权点**：不通过就停，已完成的
> 部分都可安全丢弃（除 STOP-3 之后的写盘，见回退）。

### 阶段 P0 — 前置（不碰任何存档）
1. **P0.1 备份**：`python tools/editor-bridge/backup-account-saves.py create --label terrain-writeback-pre`
   （`backup-account-saves.py:102`），随后 `verify --backup <DIR>`（`:140`），要求 `ok:true` 且
   `fileCount`/`totalBytes` 与用户预期相符。**这是本实验的第一道、也是最重要的一道闸。**
2. **P0.2 记录基线**：对 T 与 C 各记**整文件 sha256 + field-7 sha256 + 大小**（只读）。预期 field-7 sha =
   `1c9d2287d86fbd98`。同时**只读**清点 `Beyond_Local_Save_Runtime*` 运行时缓存是否也存在、是否含同名关卡
   数据（`backup-account-saves.py:8` 明说运行时缓存**不在备份集内**——若它是写入方的真实来源，需单独处理）。
3. **P0.3 游戏状态**：**游戏与编辑器全部关闭**（或至少 T、C 都**未被打开**）。写入必须发生在**无写入方
   持有**的时刻，否则退化成已判定的持有态。
4. **P0.4 复核**（若是真机动作）：按工程纪律，"live restore / 文件级干预"类动作**需要独立审查**
   （`TERRAIN-WRITE-RISK.md` §5，引 `PROGRESS-BY-FUNCTION.md:123`）。本实验的每次**写盘**前须有一次
   对"目标文件、预期字节、回退路径"的第三方核对。
   - **STOP-1**：备份 verified + 基线已记 + 状态确认（游戏/编辑器关）。**任一不满足 → 停。**

### 阶段 P1 — 离线产出改过的字节（不碰存档）
5. **P1.1**：`read_level(T)` → `terrain_fields_of` → `set_cell(terrain, 100, 100, 2)` →
   `apply_terrain_fields(level, fields)` → `to_level_bytes(level)`，得到候选字节 `B_T`。
6. **P1.2 离线自检（must pass）**：解码 `B_T`，要求 **①** cell(100,100)=2、其余 399 格=1；
   **②** 整文件大小不变；**③** 与 T 原字节**恰好 1 个字节不同**、偏移确定（§1.2 期望 18058，实际以当次为准）；
   **④** 除 field 7 外其余字段逐字节不变。对 C 同样产出 `B_C`（同样改一格）。
   - **STOP-2**：P1.2 四项全部通过 → 才允许进入写盘。**否则停，重查编码器。**

### 阶段 P2 — 写盘（唯一一次触碰存档，需 STOP-1+STOP-2+复核）
7. **P2.1**：用 `gil_container.write_bytes(T, B_T)` 与 `write_bytes(C, B_C)`（`gil_container.py:553`）。
   **仅此一处落盘**；不碰 `.gip`、不碰 Runtime 缓存。
8. **P2.2 写后立即独立读回**：重新从磁盘读 T/C，要求 sha256 与 `B_T`/`B_C` **逐字节相同**、与预热基线
   差 **1 字节**。
   - **STOP-3**：读回不符 → **立即按 §6 回退**并停。

### 阶段 P3 — 让写入方跑一次（唯一需要用户动作的一步）
9. **P3.1（用户执行）**：打开编辑器，**只打开 T**，做**一次会触发 save 的编辑**（就是会给 field 6 追加的
   那种 save），然后**关闭编辑器**（`TERRAIN-WRITE-RISK.md` §5 第 4 步）。**全程不要打开 C。**
   - **STOP-4**：用户动作。

### 阶段 P4 — 判定
10. **P4.1 只读复核**：读 T 的 field-7 sha 与 field 6 条目数；读 C 的 field-7 sha。
    - **正对照（save 确实发生）**：T 的 **field 6 出现了新的追加**（否则本次 save 未生效，实验无效，见 §6）。
    - **T 的 field-7 sha 变回 `1c9d2287d86fbd98`** → 写入方在打开时**未重读磁盘**（或从别处覆盖）⇒ **关闭态写入也被抹**。
    - **T 的 field-7 sha 仍是编辑 sha（`cba22141...` 类）** → 写入方**打开时重读了 `.gil`** ⇒ **关闭态写入可跨会话存活**。
    - **C 的 field-7 sha 应为编辑 sha**（从未被持有）；若 C 也被抹回默认，说明现象的自变量不是"是否被持有"，
      结论作废（§6）。

## 六、判定与"失败"的定义

**三态判定**（引用时只用在 §P4 实测数据上）：

- **CONFIRMED-覆盖**：T 回到默认 sha **且** field 6 有新增（save 真发生）、C 保持编辑 sha
  ⇒ 关闭态写入也被覆盖，`TERRAIN-WRITE-RISK.md` §3.2 的缺口闭合到"不存活"这一侧。
- **CONFIRMED-存活**：T 保持编辑 sha **且** field 6 有新增、C 保持编辑 sha ⇒ 打开时重读了磁盘。
- **无结论**：field 6 **无**新增（save 没发生）、或 T 与 C 的结局**相同**（自变量不成立）、或读回有歧义
  ⇒ 作废，**重做时必须换一份新鲜基线**（`CLAUDE.md` §四：复用基线会报冲突）。

**"失败"的层次（务必分开）**：

| 层 | 形状 | 严重度 | 可恢复？ |
|---|---|---|---|
| 仪器失败 | P1.2 自检不过 / P2.2 读回不符 | 低 | 是（未生效或立即回退） |
| 无结论 | save 未触发 / 自变量不成立 | 低 | 是（换新鲜基线重做） |
| **软损伤** | T 或 C 被写得游戏无法解析/加载 → 编辑器打不开该关 | **中** | 是（从备份覆盖还原，但需受复核的第二次写） |
| **硬损伤** | 事故波及**账户集内其它文件**（如 `.gip`）、或波及**用户主关卡** | **高** | 部分（备份能还原，但用户可能已在此窗口继续工作，覆盖会吞掉新进度） |
| 史无前例 | 游戏/编辑器把 T 的异常地形**扩散**到别的关卡或账户态 | **未知** | 未知 |

**设计上的防线**：T、C 都选**低价值**关卡 + **只改 1 字节** + **只有一次写盘动作** + **先备份后写** ⇒
即便走到"软损伤"也能回退；硬损伤的唯一通道是"写错文件"（用 STOP-1/STOP-2 的目标核对封死）。

## 七、风险，直说（可能丢什么、能不能恢复）

1. **可能丢什么**：实验直接对象只有 T、C 两关。**最坏**是这两关的地形被写成一个游戏不认的形状，
   使该关**打不开或被引擎重写**——损失内容是"实例摆放测试"级别的测试场地。**理论上**还可波及
   同一次 save 里被写入方重刷的**其它**文件（若"整文件重写"的推断成立，只有被持有的那关会被重写，
   但这不是我们能保证的）。
2. **能恢复吗**：**能，但代价不便宜**。备份工具（`backup-account-saves.py`）能**完整**还原账户集，
   但它的 `restore` **只进 sandbox**（`:170-191`）；真要盖回活档，需要**又一次受复核的写**——
   而在"备份→事故→还原"的窗口里，用户若继续在同一账户上工作，覆盖会吞掉那部分进度。
3. **不可逆的那一小块**：`backup-account-saves.py:8` 明说**运行时缓存不在备份集内**。若写入方的真实
   来源恰是运行时缓存，本实验可能**改不到也要保护的那一格**，或者暴露一个**备份盖不住**的状态。
   这是"先清点缓存"（§5 前置 5）存在的原因。
4. **恢复的复现性风险**：`TERRAIN-WRITE-RISK.md` §3.1 已经记录过一次"文件级恢复**不能治本**"
   （还原后下一次 save 又追加回去）。地形若同机制，**"还原"本身也可能被下一次 save 重演掉**。

## 八、值不值得（本任务要的诚实回答）

**结论：不值得现在做。建议推迟到"写入方粒度"这一问落定、且真出现"地形要落盘"的需求之后。**

理由，按含金量排序：

1. **它要回答的那一半，答案是"用不上"的**。§2 的 Q（关闭态写入能否存活）即便答成"能"，也**不解锁任何
   产品能力**：本工程**没有地形写入原语**——桥的 op 面里 `terrain` 0 命中（`CLAUDE.md` §五），
   节点目录里也没有"创建/修改地形"节点（`TERRAIN-STATUS.md` 断言③）。⇒ 我们只能**在磁盘上偷改**，
   而用户在该关里**再编辑一次地形**，写入方就会从内存重刷把它抹掉。答成"能"只换来一个
   **会被下一次正常操作抹掉**的临时状态——不是能力，是"能和写入方赛跑多久"的脚注。
2. **它的另一半已被判定**。持有态写回 = **会被覆盖**（`TERRAIN-WRITE-RISK.md` §3.1，有实测前例）。
   §2 的实验**刻意只做那一半**，所以能拿到的净值很小。
3. **成本不是字节，是真存档**。改动面（1 字节）几乎为零，但**动作面**是：一次真机写 + 一次用户 save +
   **可能的一次受复核覆盖还原**，落在**用户的真实账户**上。用"一份真存档的安全"换"一条用不上的结论"，
   不值。
4. **前置条件还没就绪**。`TERRAIN-WRITE-RISK.md` §5 的 **E1**（纯只读、把整文件/字段差分扩到全部
   `scene-cli` save 留档）**现在就能做、零风险**，且它正是判断"写入方粒度"的补强证据。**先把 E1 做掉**，
   比跳去做 E2 便宜、也更该先做。
5. **何时值得做**：当且仅当**同时**满足——(a) "写入方是否整文件重写"这一问已有直接证据落定（现在是"强推断"，
   见 §1.3）；(b) 真出现"地形必须持久化"的需求（例如未来挖到了地形写节点/API，或产品需要它）。
   在那之前，**field 7 的正确用法是只读证据源**（默认 sha `1c9d2287d86fbd98` 当基线锚）。

> 换句话说：本文件的价值不在"让人去跑它"，而在**把"为什么现在不跑"用 file:line 钉死**——
> 免得第四轮又有人凭感觉去动真存档。
