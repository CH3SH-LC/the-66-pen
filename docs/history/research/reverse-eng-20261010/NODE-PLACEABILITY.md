> **过 G1+G2+G3+G4 的服务端定义 = 500 / 500。** 即：**从合同库看，500 条服务端定义没有一条是

### 2.4 客户端的对照（说明 G2 真的会筛人）

同一 store 的客户端半边有 **429 条变体 / 310 个唯一 id**，类别是 `{10001,20001,22000,0}`（122）、
`{10001,20002,22000,0}`（197）、`{10001,20007,22000,0}`（110）。这些**都不等于**服务端元组

另：客户端 429 变体压到 310 个 id ⇒ **同一客户端定义可带多个类别**；服务端不是这样（500 条 500 id）。
（此段是 §4 的重要背景：**「500」这个分母本身已经是「服务端」这一半边**。）

## 5. 提醒：**可放置 ≠ 可运行**（这一条要和上面的数字一起读）

1. **「过静态闸」≠「活体注册表一定过」**。本文算术跑在**离线合同库**（录制的投影），G1–G4 是对**活体
   `resources`** 跑的。合同库与活体若漂移（版本、录制缺漏），结论会变。合同库自己是这么标的：
   `index.json` `status.runtimeVerified = "not-assessed-by-T15"`、`status.editable = "not-assessed-by-T15"`。
2. **可放置 ≠ 可连 / 可配置**。合同库**没有**一条 pin 记录 required/default/enum/dynamic-port
   （`index.json` `support.nodesWithACompleteFieldContract: 0`）；`unknowns-server.json` 里
   `ports[].defaultValue` / `enumValues` / `dynamicPortRules` / `defaultState` 全是 `unknown`
   （各 2355 次）。**放得进 ≠ 连得上 ≠ 填得对。**
3. **可放置 ≠ native 接受**。适配器自己把这条写成活的未知：静态身份充分与否**未证**，被 native 拒绝
   必须冒 `AUTHOR_NODE_READBACK_FAILED`（`AuthoringGraph.cs:336-339` / `:344`），**不许假成功**。
4. **真机只证到极小样本**：`CLAUDE.md:66` 记录「桥建 **15** 节点图 → 独立读回 → 建地块实体 → 绑定 →
   原生 save」一次闭环；`MODULE-PLAN-6.md` 头部另记 **688 / 691 两条**单独加图读回。
   **500 里真机走过的 < 20 条**。「500/500 可放置」是**静态推算**，不是**500 条真机跑过**。

> 一句话：**本文只证明「500 条都不撞静态闸」；它不证明任何一条能连、能配、能跑。**
