## 3. 核验：官方校验「是错误弹窗、不是可读报告」吗？

**结论：成立（对「试玩校验」这一类）。逐字引注如下。**

**承重原句**（`mhie54ik9ovg.txt:1`，与 live refetch html 逐字一致）：

> 「**当检测到未满足条件时，将弹出对应的错误码供创作者(奇匠)检查。**」

- 「**弹出**」= pop-up；「**错误码**」= error code；「**供创作者检查**」= 给人看的。**没有任何**词指向「报告 / 日志 / 文件 / 可导出 / 可读回」。
- distil 把它固化为 `PLAYTEST-CONTROL.json:18`：
  `onFailure: "将弹出对应的错误码供创作者(奇匠)检查 - a POPUP carrying an error code the creator inspects"`；
  并列 `whatIsNOTDocumented`（`:19-23`）三条：
  ① `no individual error codes are listed`、② `no indication that checking continues DURING the run`、③ `no log-style report of check results`。
  > **口径修正**：`whatIsNOTDocumented` 是**absence（缺席）判断**——即「文档里没写」，**不等于**「系统里没有」。
  > 三条里**唯一**由逐字正文直接支撑的是「弹窗」；另两条是**"没写"**。本文件**照此标注**，不把它们拔高成「不存在」。

**关键对照（这是官方语料里**单独**一条承重事实，必须引）**：
`mh0xm3ryh9hq`（风险检查功能）的 `facts` 里有一条 `behaviour-contract`，逐字：

> 「**试玩校验中的错误会阻止试玩的正常进行，属于比较严重的阻碍性错误，会导致功能无法正常运行；而风险检查中的提示则不会阻止试玩，不会影响功能的正常运行，一般是数据上的错误。**」

并且该章**确实**描述了**可读的检查结果面**（`facts` 逐字）：

> 「**点击【发起检查】即可对当前的奇域进行检查**」「**左边时间表明该次检查发起的时间 / 右边则全量显示当前奇域所检查出的风险项**」
> 「**检查记录的存在上限为5条**」「**检查记录仅在当次编辑时保存，重新加载存档则会清理掉之前的记录**」

⇒ **两层要分清**（否则会把结论说过头）：
- **试玩校验（阻塞型）**：只有**弹窗错误码**，**无可读报告**。**(b) = 不能。**
- **风险检查（非阻塞型）**：有**可读的记录面板**（≤5 条、列表全量显示），但它**不阻止试玩**、且**与试玩校验分属两类**。
  ⇒ 项目里**能读到**某份「检查结果」的是**风险检查**，**不是**试玩校验的**门禁结果**。
- 另有一条**旁证：官方并非没有"可导入的报告"这种东西**——`MULTIPLAYER-PLAYTEST.json:44-47` 记多试玩结束会生成 `Beyond_Performance_Report`（**性能**报告，可导入查看）。**它也不是校验结果**。
  ⇒ 官方有能力产出**文件式**产物（性能报告）与**面板式**产物（风险检查记录），**但偏不给「试玩校验」做这两样**——**这坐实了 (b) 是 by design，而非遗漏**。

## 4. 诚实判决：`playtest.control` 的可达性

**在官方证据下，`playtest.control` 没有可编程落点。** 理由自上而下：

1. **入口是 UI-only**：官方给的是「系统菜单——试玩 → 按钮【试玩】」（§2.1），**无命令名 / 无 API / 无直达快捷键**。桥侧**零** `start-playtest`（另见 `PLAYTEST-CONTROL-MINE.md` §3.1，与本文件互不依赖，同向）。**(a) 不能。**
2. **校验结果不可读（by design）**：官方把它定义为**错误码弹窗**（§3 逐字）。要「读到校验结果」，得**读一个弹窗**——官方既未提供可读面，产品又在**别处**（性能报告 / 风险检查）证明过它能做可读面。⇒ 这是**设计缺席**，不是实现缺口。**(b) 不能。**
3. **状态改变无官方句柄**：官方只有「进入试玩 = 进入运行时」这句措辞，**没有**编辑态/运行态字段。可读判别位在代码侧仅 candidate（包 1022 / `mode+0x1cc`），**未证**。**(c) 未知。**
