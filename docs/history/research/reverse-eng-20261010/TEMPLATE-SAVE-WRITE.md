## 0. 一句话结论

**模板确实在一个我们看得见、读得出、也能字节精确重编码的字段里——但它不是任一个「小记录注册表」，
而是 `.gil root field 15`（类型化资产表，带名字）；而这两条同时成立的坏消息是：**

1. **读得到**：`root field 15` 的每条记录 = `{f1: 数字 id, f2: 计数, f4*: 组件块}`，**名字在组件块
   kind 1 里**。本机真实装着一条 **type 11 背包模板**：`id=1119879169`、`name="背包模板"`
   （`1073741831.gil`，见 §3.2 原始字节）。**这是全盘唯一「模板 = 名字 + id」的落点。**
2. **写不进（缺样本）**：全盘 **`type 8/10/15`（道具/货币/商店）实例 = 0 个**（§4）。要手写一条
   不存在的类型的记录，必须知道它的 `f4` 组件块 schema——**本机一个样本都没有**。
   即便写**已存在**的 type 11 背包，也没有任何代码把改过的 `field 15` 写回文件
   （`write_bytes:553` 无人对 `field 15` 调用，§5）。
3. **写原语的「机械」部分在**：`parse_fields`↔`encode_fields` 对全部 39 个文件**逐字节往返相等**
   （§5.1），所以「改一个字段、其余字节不动」这条加密探针是通的——它**不是**本轮障碍。
   **障碍是「不知道要构造什么字节」，不是「写不下去」。**

**⇒ 判决**：写模板**直接进存档**这条路 **在本机字节层面 UNPROVEN**——不是「被禁止」，而是
「**目标类型的序列化样本不存在**，无法凭空构造合法 `field 15` 记录」。能确定的是
**模板在可见字段里（`field 15`）**，不是「模板不在任何字段里」。

## 5. 写路径：机械部分在，目标 schema 不在

### 5.1 机械部分 —— **在**（已只读验证）

`gil_container` 的通用 walker 对**全部 39 个文件逐字节往返相等**：


（原始代码或现场命令片段未随公共研究笔记分发；可用工具见目录。）


- `encode_fields(parse_fields(payload)) == payload`（`:176`/`:209`）——这**正是**「改一个字段、
  其余字节精确保留」的基础，也是 `gil_container.py:14-18` 自述的往返性质。**所以「写不下去」
  不是障碍**；能字节精确重编码，且写口 `write_bytes`（`:553`）存在并被关卡注册/备份路径调用。

### 5.2 唯一缺的 —— **目标类型的序列化样本 = 0**

- **没有 type 8/10/15 的实例可照抄**（§4）。`field 15` 里能照抄的只有 type 11 背包（组件 kind
  `[1,42]`）、type 27 环境、type 4 职业、type 5 成长曲线——**它们的 `f4` 组件布局各不相同**
  （§3.2），**无法从一个类型外推到另一个类型**。
- **没有 `field 15` 的构造器**：`gil_container` 的 builder 只覆盖 name（`build_level :289`）、
  level list + tabs（`build_profile :449`）与 level_ref（`build_level_ref :526`）——
  **没有一个函数碰 `field 15`**。全仓对 `write_bytes:553` 的调用（`keep_registered.py`、
  `register_level.py`）都只写 profile 的关卡引用与 level 的 name/id，**没有任何调用方写 `field 15`**。
- **⇒ 「能改一个字段值」≠「能构造一个本机不存在的类型的记录」。** 这是本轮的硬结论。

### 5.3 三层分开（不得混称）

| 层 | 结论 |
|---|---|
| **文档写了什么** | 官方有货币(10)/道具(8)/背包(11)/商店(15) 四类配置 ID（`mhsd6lrx3voe.json:66`），入口在系统菜单。（`TEMPLATE-CREATE-TRACE.md §7`） |
| **工具/源码能做什么** | **读**：`parse_fields`/`parse_profile` 现场解出 `field 15` 的 id、名字与 `f4` 组件 kind（本文件字节）。**写**：`write_bytes:553` 是全仓唯一写口，**无调用方写 `field 15`**；无 8/10/15 样本可构造。 |
| **真机验证过什么** | 本轮**零执行**。`field 15` 的结构/名字/id 是磁盘真实字节读出的 `static` 级证据；「写不进去」是**静态判定**（无样本、无构造器），**未经真机写实验**。 |
