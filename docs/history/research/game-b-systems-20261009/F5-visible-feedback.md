# F5 玩家可见反馈：官方手段 & 我们的覆盖

一句话结论：**最省事的路 = 往界面布局放一个「文本框界面控件」，内容写变量占位符 `{1:lv.钱数}` 或 `{1:ps.钱数}`——变量一变文本自己就更新，不需要任何"推送"节点**；想在世界内看见，就把「文本气泡组件」挂到告示牌/提示牌物件上，它的文本内容同样支持插入变量。正式的路 = 官方 HUD 控件（进度条/计分板/道具展示/消息队列）。**我们这一侧的 op 面（见 tools/gameplan/tests/test_doctrine.py）里没有一个能配 UI**，这条路目前只能手工在编辑器里配。

## 1. 官方提供的玩家可见反馈手段（按实现难度从省事到正式排序）

1. **文本框界面控件 + 插入变量**（最省事）。文本内容里写占位符，变量变则运行中文本实时更新；无需节点推动。
2. **文本气泡组件**（世界内）。挂载于实体（支持物件、造物），文本内容也支持插入变量；世界空间可见，最贴合"世界内提示牌"。
3. **图文输入框控件**（文本框的另一种变体，同属界面控件组编辑窗口可添加项）。
4. **文本视窗控件** = 文本框 + 滚动；字段同源，另给脚本句柄 `TextWindowControl`。
5. **道具展示界面控件（模板道具型）**：开「道具数量展示」后，图标正下方直接显示数量；数量绑「道具数量变量」。
6. **进度条界面控件**：进度样式选「当前值」即把变量原值实时显示出来。
7. **特殊数字控件**：只认 技能 / 道具 / 单位状态 三种数据来源（**不是任意自定义变量**），由节点图唤起。
8. **计分板界面控件**：关卡运行时展示**玩家自定义变量**并按该变量排名。
9. **消息队列控件**：由**服务器节点「更新消息队列」**按一份结构体整体推送（唯一自带"推送节点"的显示控件）。
10. **悬浮交互页控件 / 网格视窗控件 / 自定义开关控件**：面板、列表与双向绑定类，挂客户端脚本，属"正式但重"的一档。
11. **前置容器：客户端控件容器**——不是显示手段本身，但**没有它，界面布局里所有客户端控件都不显示**。

## 5. 结论：给「钱数 +10，玩家看得见」这件事选哪条路

- **推荐主路（最省事）**：把"钱数"存成**关卡级自定义变量**（`lv` 前缀）；在**界面控件组管理**里新建/编辑一个界面控件组模板，加**文本框界面控件**，文本内容写 `{1:lv.钱数}`（或玩家自身变量用 `{1:ps.钱数}`）。**变量一变，文本自己更新——不需要任何推送节点**。加钱的 `+10` 那一步才是节点图的事（F1/F2）。
- **务必先确认的前置**：该界面布局里**必须有「客户端控件容器」**，否则文本框不显示（`mhlz2lrly3dq` 的全称硬约束）。这是最容易被忽略、且现象是"什么都没出现"的一坎。
- **想要世界内看见**：把「**文本气泡组件**」挂到告示牌/提示牌物件上，文本内容同样插入变量。注意**一个组件同时只生效一个气泡**，切换要用节点「切换生效的文本气泡」。
- **正式 HUD**：若"钱"是纯数值，最贴的是**进度条控件**（进度样式=当前值）或**计分板**；若是"道具数"，直接上**道具展示控件（模板道具+道具数量展示）**。**消息队列**是唯一自带服务器推送节点的显示控件。
- **不建议**指望用「特殊数字控件」显示钱数：它的数据来源只有 技能/道具/单位状态，没有"自定义变量"。
- **我们这一侧**：UI 的配置**目前没有任何自动化入口**（桥的 op 面（见 tools/gameplan/tests/test_doctrine.py）无 UI op），只能在编辑器里手工配 —— 或者等 7.1 Lua 客户端脚本链被接通（有原生后端，未验证）。
