# M2 货币 + M3 道具：官方系统 & 我们的覆盖

**一句话结论：官方两套都有，而且都是「有 配置ID 的一等编辑器模板」——货币（配置ID 类型 10 `资源货币`）与道具（类型 8 `普通道具、装备道具`）各自有专门的编辑页面与完整字段表，所以 M2/M3 在玩法设计意义上是「配一配现成的」，不是从零搭。但和我们另一路对 M4/M5 的判定一样，「配一配」的主动权不在我们手里：全部配置项只在编辑器 UI 里（系统菜单 →【货币与背包】→ 货币/道具页签），而 `tools/authoring/INTERFACE-INVENTORY.md:45` 把 `game.items` 标为 `research / 尚无完整入口`，桥接的 op 面（见 tools/gameplan/tests/test_doctrine.py）里**没有任何一个**能创建或修改货币模板、道具模板、背包模板、商店模板。**

## 1. 官方有没有现成的货币系统（有）

**有。** 三重证据，互相独立：

1. **专章**：`mh2cr30yeak0` 题为「货币」，是「概念介绍 › 高级概念 › 资源系统」下的实质正文页（499 字，`pageNature=substantive`），给出定义句 + 7 个字段行，且**给出入口与页签**。
2. **配置ID 类型表**：`mhsd6lrx3voe`（ID修改）的「2.ID类型表」里，货币占一行 —— 单元格逐字 `资源货币`（类型号 `10`，十进制可修改范围 `1115684864~1119879167`）。同表另有 `普通道具、装备道具`=8、`道具背包`=11、`装备模板`=19、`商店模板`=15。
3. **系统菜单入口**：`mhn4bsi5lb58`（整体界面）的菜单项清单里逐字含 `背包与货币`；`mh2cr30yeak0`/`mhogfq9bf86q`/`mhkl2yin0cxo` 三章都用同一句 `通过【货币与背包】按钮进入编辑界面`。

定义原文（逐字，已回源）：`货币是玩法中的一般等价物`，`用于标定虚拟道具的价值`，且**可被单位持有**、随交易或节点图逻辑增减。

**边界**：本章 `whatThisChapterDoesNotSay` 11 条，其中三条对 M2 最重要 —— 未给「显示优先级」的数值范围/上下限/默认值；未给可创建的货币数量上限；未定义「虚拟道具」。**「货币」在本章只是一条带名字的状态 + 一条掉落规则，没有任何交易机制描述**（交易在商店章）。

## 2. 官方有没有现成的道具/物品系统（有）

**有，而且是整个「资源系统」家族里最厚的一章。**

1. **专章**：`mhbgx0rspbqu` 题为「道具」（1149 字，substantive），三节结构 = 定义 / 分类 / 编辑，字段按「1.基础设置 / 2.掉落设置 / 3.交互设置」三分组，**共 24 个具名字段**。
2. **分类枚举**：`道具被分为装备、材料、消耗品、贵重物品几类`（四类，章节未给第五类）。
3. **同族页**：`mhkfj1iilnck` 掉落物、`mhkl2yin0cxo` 装备、`mhogfq9bf86q` 背包、`mhi9s7isvp50` 商店、`mh5y5001vqd4` 背包组件、`mh63ox06afy8` 战利品、`mho6gviqhsqs` 商店组件 —— 道具不是孤立的，它是一棵有 6 个子页的树的根之一。
4. **装备是道具的子类型**（逐字）：`装备是一种道具的子类型`（`mhkl2yin0cxo`），新建路径就是「道具页签 → 新建道具 → 下拉【选择类型】→ 选装备」。

**「道具模板」是编辑器资产，不是可摆放素材**：`配置ID：道具模板的唯一标识，可在节点图中使用` —— 即节点图引用道具**只用配置ID**，且该 ID 属于类型 8。

**边界**：`mhbgx0rspbqu` 的 `whatThisChapterDoesNotSay` 12 条。对 M3 最要紧的三条：未给「堆叠上限」任何数值范围；未给「配置ID」的取值类型/格式/是否自动生成/跨关卡是否唯一；未说明「关联道具节点图」能挂几张、入口事件是什么、离开背包是否解绑。**本章 7 张截图（4 宽幅界面图 + 3 窄幅面板图）一张未读**，面板布局只在图里。

## 5. 结论：配一配 vs 要新开工具

### M2 货币

### M3 道具

- **玩法设计层面：配一配** —— 官方道具模板有完整三组 24 字段，含 `关联道具节点图：当道具进入角色的背包时，关联的节点图会被附加到角色单位上` 这条**官方给的挂图时机**；装备是它的子类型（词条系统可复用）；掉落/拾取规则在掉落物内容组件里现成。

### 对 MODULE-PLAN-6 §一 的修正

计划原话「**道具/货币/背包/商店全部压在变量这上面**」**说得过头了**，应改为：

> **存储不压在变量上**（存储是官方模板 + 背包组件 + 61 个现成节点，图工具面很可能已够用）；**压在变量上的是"显示"**（界控件绑定…变量）与**"自定义逻辑"**。
