# M1 交互点：官方系统 & 我们的覆盖

**一句话结论**：官方**有**现成的交互触发系统，而且**不止一套**（UI 按键类 `界面控件` 与实体空间类 `碰撞触发器/触发源`＋`掉落物拾取规则`），所以 M1 本该是「配一配」；但**我们这一侧目前一条配置项都改不到**——62 项（文件内实测 case 全表（见 tools/gameplan/tests/test_doctrine.py）bridge 操作里没有一条触及界面控件、通用组件或拾取规则，故实际形状是「配置目标已存在，但我们缺一条写入口」。本次零执行。

## 1. 官方有没有现成的交互触发系统

有，且分成**两族、三处入口**（均为文档层证据，`docs/official-docs/chapters/*.json`）：

- **A. UI 按键族（点/按触发，不靠近）**：`交互按钮界面控件`（`mhwkfsitckrw`）、`自定义按钮控件`（`mhtpwgitsigc`）、`道具展示界面控件`（`mhjja1ipq9ck`）、`自定义开关控件`（`mhkrafr3w6um`）、`悬浮交互页控件`（`mh2u2e9o3jn6`），总索引 `界面控件`（`mhnapxrumtzy`）。统一出口是节点图事件**「界面控件组触发时」**。
- **B. 实体空间族（靠近/进入触发，不按键）**：`碰撞触发器`（`mh8w69rzuc3i`）＋`碰撞触发源`（`mhn95di01j84`，一对通用组件），事件**「进入碰撞触发器时」/「离开碰撞触发器时」**。
- **C. 物件自带交互（靠近＋按键二者可配）**：`掉落物`（`mhkfj1iilnck`）的「拾取规则」枚举，是唯一把「靠近自动」与「靠近显示按键」并列成选项的一处。

### 两个必须明确回答的问题

1. **「靠近自动触发 vs 按键触发」——两者官方都有，但在不同系统里。**
   - **按键触发**：A 族界面控件只有「点击/按键/外接设备输入」，**全无 proximity**（`mhwkfsitckrw` verbatim：「关卡运行中，点击和外接设备输入，都可以触发该界面控件的交互」）。
   - **靠近触发**：B 族碰撞触发器纯空间——「关卡运行中，"碰撞触发器"持续监测其他携带"碰撞触发源组件"的实体」（`mhn95di01j84`）。**文档未述**碰撞触发器有按键成分。
   - **两者可同选**：只有 C 族掉落物的「拾取规则」把二者并列：「交互拾取」=靠近显示按钮＋按键拾取，「自动拾取」=靠近即拾，「打开拾取界面」=靠近显示按钮＋开界面，「自动吸附拾取」=先吸再自动拾（`mhkfj1iilnck`）。但该枚举只属于掉落物，**不能推广到通用交互点**（`mhkfj1iilnck` 只说掉落物内容组件）。
2. **「触发组件配在物件上还是关卡里」——配在物件（元件/实体）上或作为 UI 资产存在，不是配在关卡里。**
   - 碰撞触发器/触发源 = **实体**的通用组件（`mh8w69rzuc3i`/`mhn95di01j84` verbatim：「组件编辑页签 / 添加通用组件 / 碰撞触发器 / 详细编辑」）。
   - 掉落物拾取 = **元件**上的掉落物内容组件（`mhkfj1iilnck`：「所有掉落物类型的元件会固定携带一个掉落物内容组件，不可被移除」）。
   - UI 交互按钮 = **界面控件资产**，在「界面控件组编辑窗口」编辑，再由「界面布局」引用、经**职业**配给玩家（`mhewyi0fjfvs`/`mhozt0r74ng6`）。
   - 关卡层只有「界面布局库」这一容器（`mhewyi0fjfvs`：「界面布局库不可为空，最少包含一个界面布局」）与布局的默认应用，**没有把交互触发配在关卡上的字段**。

## 4. 结论：配一配 vs 要新开工具

**分两句，缺一不可：**

- **对官方系统：M1 是「配一配」。** 交互触发、靠近范围、按键映射、玩家作用域、事件名都已由官方提供且带完整字段名（第 2 节），不需要我们从零造一套「变量＋距离轮询」。
- **对我们这一侧：现有 bridge/CLI/MCP 是「改不到」，必须先开工具。** 62/136 项 bridge 操作、`author.py`、`scene_cli.py` 里**没有一条**触及界面控件字段、通用组件字段或拾取规则（第 3 节）。要落到「配一配」，前置条件是新增一条能写这些配置的入口——最低限度是：① UI 资产侧（界面控件组/控件字段）读回与写入；② 实体通用组件（碰撞触发器/触发源）读回与写入；③ 节点图侧把「界面控件组触发时」事件接进我们自己的图。在此之前，M1 不能靠现有工具交付。
- **旁路（值得先试）**：纯**节点图**路线不需要写任何界面控件字段——官方节点全目录里已有「界面控件组触发时」（id 316，**带出参** 事件源GUID/界面控件组组合索引/界面控件组索引/事件源实体）与执行节点「激活控件组库内界面控件组」(383)、「设置界面控件(组)状态」(384)、「移除控件组库内界面控件组」(521)（`NODE-CATALOG.md:839/863/864/896`）。若 `graph.nodes` 从「71/1 固定」推广到「按 definitionKey 加任意节点」，M1 的「操作→可见变化」可全部走节点图，**绕开①/②**——这是当前性价比最高的一条待验证路径，但**尚未实测**。
- **其他旁路**：B 族（碰撞触发器）在官方侧语义最贴近「靠近」，卡在②；C 族掉落物拾取语义最全，卡在①/②。**在①②未打通、③未验证前，没有一条现有 op 能端到端交付。**
