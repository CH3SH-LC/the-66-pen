# M4 背包 + M5 商店：官方系统 & 我们的覆盖

**一句话结论：用户那句话被原文证实。** 官方确有自带的背包系统与商店系统，且不止一套：两者都是「**全局模板（编辑期）→ 实体上的组件（引用方）→ 运行时实例**」的三层结构，商店还另有「商店模板管理」这一整块编辑器面板。因此 M4/M5 在**玩法设计意义上**是「配一配」，不是从零搭。**但「配一配」的主动权不在我们手里**：全部可配置项都在编辑器 UI 里（【货币与背包】/【商店模板管理】），而我们的工具面**没有任何一个操作能创建或修改这两类模板、也没有任何一个组件写入路径**——见 §4。

---

## 1. 「背包组件」vs「背包」是什么关系

不是「组件 vs 界面」，而是**同一系统的两个不同编辑对象，分处两棵文档树**。

| | 章 | 树位置 | 是什么 |
|---|---|---|---|
| **背包** | `mhogfq9bf86q` | 概念介绍 › 高级概念 › **资源系统** | 「整个资源系统的容器」；本章真正讲的是**背包模板**的定义与字段（【货币与背包】→ 背包页签） |
| **背包组件** | `mh5y5001vqd4` | 概念介绍 › 功能 › **通用组件** | 挂在**实体/元件**上的组件；在实体或元件编辑界面 → 组件编辑页签 → 添加组件 → 「背包」 |

引用链原文（两句互补，均逐字核过源文）：
- `背包组件将直接引用背包模板，并在运行时生成对应的背包实例` — `mh5y5001vqd4`
- `在实际游玩时，背包模板定义由背包组件进行引用并实例化` — `mhogfq9bf86q`

即：**模板是配置，组件是引用+实例化者，背包实例是运行时产物**。第三节「背包运行时实例」在**两章都只有标题、正文在配图里**（`mh5y5001vqd4` 10 条 notSay 之一明写；`mhogfq9bf86q` 只有一句话）。

另有三条可比对点：「背包」被官方同时当作**虚拟物品的一类**（`mhkfj1iilnck`：`包括道具、装备、货币、背包`）和**配置ID 类型 11**（`mhsd6lrx3voe` ID 表行首词 `道具背包`）；「装备」是道具的子类型、同样走背包管理（`mhkl2yin0cxo`：`装备是一种道具的子类型`）。

## 2. 「商店」vs「商店组件」vs「商店模板」是什么关系

三者是同一条链的三个名字，**「模板」二字不是"可复制的预制资产"**：

| 名字 | 章 | 是什么 | 在哪配 |
|---|---|---|---|
| **商店** | `mhi9s7isvp50` | 数据类型定义 + **商店模板**的全套字段表 | 系统菜单 →【商店模板管理】 |
| **商店组件** | `mho6gviqhsqs` | 挂实体的组件，**本身不存商品配置** | 实体或元件编辑界面 → 组件编辑页签 →「添加通用组件」→「商店」 |
| **商店模板** | `mhi9s7isvp50` | 「一份完整的商店信息配置」，全局定义 | 同上，按钮「新建商店模板」 |

- 定义原文：`商店是一种提供虚拟物品交易的模块，以组件的形式挂接在实体上。`
- 模板形态：**编辑器内的配置记录**——有唯一 `配置ID`，在 ID 体系中是**类型号 15**（区间 `1136656384~1140850687`，`mhsd6lrx3voe` ID 表）；入口是系统菜单的 29 项管理工具之一「商店模板管理」（`mhn4bsi5lb58`）。**不是可拖拽的预设/预制件**。
- 组件侧引用：`商店模板：引用一个全局定义的商店模板`（`mho6gviqhsqs`）；一个组件可承载多个商店（`商店组件支持同时配置多个商店`），按**商店序号**互相隔离。
- 商店只有两种基础类型：`商店分为两种基础类型` = 「自定义商品商店」/「自身背包商店」。

## 5. 交易逻辑是官方自动还是要自写节点图

**结论：交易本身是官方自动的，节点图只负责"配表 + 开关界面 + 收事件"。**

- 商店本体被定义为**交易模块**（§2 首句），不是需要自己实现的心智模型。
- 打开界面即官方内置：`在游戏运行过程中以玩家实体的视角打开商店`（`mhw66orrrfkm` §三十七-1），入参 `玩家实体 / 商店归属者实体 / 商店序号` —— 是**以玩家视角打开官方商店 UI**。
- 购买/出售由玩家在界面里完成，官方原文直接描述交换行为：`自身背包商店：发生购买行为时购买者和商店持有者会实际进行背包内虚拟物品的交换`（`mhi9s7isvp50`）。
- 价格表配好即成交：`售价：在进行交易行为时，买方购买一个该道具需要的货币量` / `收购价：…商店收购一个该道具会返还的货币量`（`mhi9s7isvp50`）。
- 节点图能做的三类事（`mho6gviqhsqs` 20 节点）：① 改表 —— `向自定义商店出售表中新增商品`、`从物品收购表中移除物品`、`修改…出售信息`；② 开关 —— `打开商店` / `关闭商店`；③ 事件 —— `商店出售背包物品时` / `商店出售自定义商品时` / `商店收购道具时`。
- **一处官方原文说得很硬**：`仅有背包商店中的物品交换会触发该节点，自定义商店不会触发`（`mhn7ko01v3yw` #47）——按类型分叉的事件语义，不是我们自选的。
- **本次检索范围内未找到**「一物换一物 / 以物易物（不涉货币）」的官方字段：售价/收购价的定义里都写着"货币量"。要严格以物易物，只能**自写节点图**（用 `增加背包道具数量` / `增加背包货币数量` 自己扣加）——这一点属我的判断，无官方原文支撑。
- 限量：`是否限量` 只在**自定义商品出售表**；执行节点侧 `是否限购 / 限购数量` 亦只出现在自定义商店与收购侧节点上。

## 6. 结论：配一配 vs 要新开工具

- **M4（背包）→ 配一配，但"配"要靠手工/需补工具。** 理由：模板字段（背包模板名称/背包格数量/销毁时掉落形态/战利品掉落形式/对应掉落物外形）、组件字段（背包模板/初始物品）、16 个节点**全部现成**；我们缺的不是系统，而是**触达配置项的入口**。若 M4 必须脚本化，需要新开的是"面板打开 + 字段写入"，**不是**背包系统本身。
- **M5（商店）→ 配一配，且交易逻辑无需自写。** 理由：商店模板四段配置（含两张价格表）+ 商店组件 5 项 + 20 个节点**全部现成**，买卖是官方行为。同 M4，缺的是入口。**唯一的"新工具"候选**是把 `PanelOpen` 的目标从 2 个标签扩到「商店模板管理」「货币与背包」（技术上同一机制：按标签精确匹配并 `DynamicInvoke` 编辑器自己的菜单 Action），但这只能**打开面板**，读不到也写不了字段值与价格表。
- 若允许"人在编辑器里点、工具只做验证"：M4/M5 立刻可做，因为**参照物（模板的配置ID + 两张价格表）在真机里可读**。
- 若要求"全程脚本无人工"：M4/M5 都需要先补 `entity.properties` 那条路（组件/全局模板的读写），目前是 `research`。
