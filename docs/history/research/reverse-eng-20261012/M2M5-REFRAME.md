## 0. 一句话判决

**店主的模型是对的，而且它把世界从「两层」改成「三层」——旧负面里有一整类是把 T2 层错当成了 T1/T3。**

- **T1 全局模板/配置**（配置ID）：货币(类型10)/道具(8)/背包(11)/商店(15)。**实体无关，只在编辑器 UI 建。**
  这一层我们**确实够不到**——旧负面在这层成立。
- **T2 关卡级系统**（无实体，按玩家/按索引寻址，**由输入或 NPC 交互触发**）：界面控件组、界面布局、
  **悬浮交互页**、奇域礼盒、聊天频道、排行榜…… 这一层旧检索**从没搜过**，因为旧词表里没有它。
- **T3 实体级组件**：商店组件/背包组件/碰撞触发器挂在实体上。旧负面**全压在这层**。

**净变化**：M2/M3/M4 的运行时半边**不只「很可能能」，而是宿主槽位可以由恒存的玩家实体填满**——
「不依托实体」在运行时被满足，因为玩家实体永远存在，无需我们创建任何东西。**M5 的「按键触发」不是节点，
是 T2 的界面控件/悬浮交互页交互**（点击或外接设备输入），其事件节点 316/826 我们已有。

## 5. 哪些场景半边变可达、经什么原语（任务 Q3 收口）

**新可达（旧模型里看不见）**：

1. **M1 触发半边由 T3 移到 T2。** 「按键触发」= `界面控件组触发时`(316) / `悬浮交互页操作触发时`(826)，

## 6. 结论（任务 Q4 要求：不要只是复述旧结论）

**不是「图半边已做尽、场景半边仍只差 UI 建的模板」。** 正确的是：

> **图半边比旧模型以为的更能干——M2/M3/M4 的宿主槽全可由玩家实体填满，运行时半边不再依赖「创建带组件的实体」；
> M1 的输入触发是关卡级 T2 资产（界面控件组/悬浮交互页），是另一类卡点；
> 真正且唯一卡在编辑器 UI 的，是 T1 模板本身（货币/道具/背包/商店模板），这一条旧负面成立、未被削弱。**

**给排期的净影响**：
1. M2/M3/M4 的图图工作**可以立即做、可以真机跑**（宿主=玩家实体），验收的**唯一**前置是「模板先有人建」。
2. M5 从「卡在字典 + 卡在商店组件」降级为「**卡在商店模板 + 一个待验证的宿主假设**」——
   `709/706` 的字典 pin 不再在关键路径上；先在**只读**下坐实「关卡实体能否作商店归属者」。
3. M1 的「按键触发」从「没有按键节点 ⇒ 做不到」改为「**做得到（316/826），但场景半边是关卡级 UI 资产，
   与实体组件是两回事**」。这需要单列一条 `PENDING-EDITOR-STEP: level-ui-asset`，不能与 `proximity` 那条混。
