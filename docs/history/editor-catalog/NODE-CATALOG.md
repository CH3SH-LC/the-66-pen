### 2.6 与旧目录 498 的差集分析（本节核心）

| 项 | 旧目录 498 | 新目录 799 |

| id 范围 | 1 ~ 300004 | 56823679191946411 ~ 18433320668088102609 |
| id 交集 | **0** | |

## 五、节点分类（category 元组）解读

### 5.1 字段 4 的真实结构（重要：与 JSON 里的 `category` 字段不同）

字段 4 是一个**混合结构**，其子字段按外层字段号分四种情形：

| 外层字段号 | 结构 | 出现 | 载体 |
|---:|---|---:|---|
| **1** | **扁平四元组**：`m = [{1:10001},{2:2000X},{3:22000},{5:K}]` | 918 条 / 799 个节点 | 节点自身的分类 |
| **2** | **扁平四元组**，同 f1 形状 | 760 条 / 671 个节点 | 第二分类（含义未定） |
| **3** | **条目列表**：每条形如 `{f:1 → 四元组, f:2 → 类型描述…}` | 7761 条 / 119 个节点 | 与引脚绑定的分类实例 |
| **4** | 扁平四元组 | 6 条 / 6 个节点 | 罕见 |

> **必须指出的既有缺陷**：`node-catalog-full.json` 里的 `category` 字段（以及 `build-node-catalog.py` 中对应的解析逻辑）**多剥了一层嵌套**，把本该是「一个外层 = 一个四元组」的结构解析成了 `[{}, {}, ...]`（662 个节点显示为 8 个空字典）。**该字段不可直接使用**；本文第五章与第三章的分组统计均为**重新解析原始 wire 后**的结果。修复方式：对每个外层 message，直接取其 `m` 列表中的 `{f, v}` 对作为四元组，不要再向下展开一层。
