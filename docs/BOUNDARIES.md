# 能力与证据边界

本次发布日期：2026-10-22。源码来自持续开发中的工程，历史陈述以其记录日期为准。

| 层 | 本包提供 | 证据与限制 |
|---|---|---|
| 可离线运行 | 接口查询、节点工作台、GIL/GIP/GIA 解析、差分、合成样本、MCP 查询 | 本次实际测试，见 VALIDATION |
| 源码实现 | authoring、helper、C# 桥、原生 C++、地形/实体/属性/试玩工具 | 编译与离线测试不是游戏验收；需要用户本机配置 |
| 历史实机 | 研究笔记中注明日期的建图/绑图/保存/字段变化 | 原始私人回执未公开，不能当本包的新实机证据 |
| 静态候选 | 原生命令哈希/地址、UI 操作、符号和组件方法 | 可检索并继续研究，不提供伪造的可调用承诺 |
| 未知或缺口 | 版本升级兼容、任意组件添加、部分泛型/动态端口/值槽、跨独立关卡传送、导入与 ACK | 保留未知，不把字符串或菜单当作接口 |

## 通道

1. `elevated-request.py call` → runner 字段白名单 → `call-bridge.ps1` → C# BridgeServer。三层都支持才可达。
2. `author.py graph` → `author-graph` 队列 → 图 transport，仅转发指定操作。
3. `scene_cli.py` 和各 native CLI → 固定准备目录/profile → 原生执行路径。桥的目录里找不到一个操作，不能证明原生通道也没有。

桥编辑的是编辑器内存。图修改必须 export，再走原生 save，才可能进入存档。`ok:true`、回执、文件大小、节点数都不能单独证明保存/玩法正确；需要字节差分、独立读回及重开/试玩证据。

## 关键研究结论

- 同一个 definitionId 必须带 graphKind；节点目录不是逐节点运行验收。
- 组件读取、删除、创建是不同能力。无 AddComponent 调用链不等于组件不存在；历史删组件依赖 reader 绑定，失败应保留错误。
- storage=1 的 int 载荷曾未证；按实际 live slots 与精确类型校验，不套用相邻节点。
- 地形格距常见 5m、层高 2.5m，必须结合会话原点/坐标帧；世界偏移只应用一次。保存字段 7 的变化仍需独立读回。
- 模板名称、几何估计、图标和视觉确认是不同层；模板目录只作查找，不是模板外观验收。
- 7.1 混淆符号可按 legacy 方法序号寻找候选，但必须校验 owner、kind、签名、static 和二进制身份。
- 历史 DS UI 表可能把类级第一条命令错配给每个控件。92 条 UI 记录统一降为 static-candidate，不复用其“已证直达”标签。
- 旧接口清单的状态可能过时；`catalog/capabilities-history.json` 保留原日期，当前具体入口见 `catalog/interfaces.json`。

## 发布排除项

不包括游戏 DLL/EXE、存档、资源图片音频、官方教程全文、原始 protobuf 资源表、完整反编译源码、DSH 安装与会话、密钥、用户配置、现场队列或日志。研究文档中的历史路径是来源标识，不承诺这些文件随包存在。

源代码中保留的指纹、RVA、协议编号和版本名服务于兼容性校验。不能删除失败即拒绝、版本检查、保护关卡、review、单请求幂等或不确定状态不重试机制来获得“成功”。

旧 level-catalog/lifecycle/scheduler/reopen 扩展曾钉住某次现场 PID 和进程创建时间；发行包已将这些会话值清零，不能直接在真实进程调用。需要按自身会话重新研究、生成并审核 profile，不得移除身份检查。核心节点查询与基础 scene 路径不靠这些私人会话值。

五个历史自连接修复／单实体清理入口仅保留明确拒绝的兼容响应 `PRIVATE_SESSION_RECOVERY_NOT_DISTRIBUTED`；原一次性私人授权及现场数据不分发。原生存档目录内存观察的历史 PID/时间也清零；离线字典解析保留。通用实体清理不等同于这些历史专用操作。
